# 7-Zip archive recovery references

7-Zip 25.01 created the nine archives from the checked-in file corpus. The manifest records the compression settings, byte length, SHA-256 and original member for each archive. It includes stored data, LZMA and LZMA2, solid and separate blocks, compressed and plain headers, BCJ, Delta, Deflate, BZip2, Unicode names and an empty member. A separate encrypted header and a PPMd archive exercise formats outside the current native decoder.

The portable test places consecutive archives across the scanner's chunk boundary. The Linux trial creates a FAT32 filesystem, copies each archived file into it, reads it back, unlinks it with mtools and confirms the directory no longer lists it. Both scan modes have to recover all nine archives with the original bytes and SHA-256. Linux additionally runs 7-Zip on the originals and recovered files, extracting every member to stdout and comparing it with its source. A damaged member fails even when both header checksums remain valid. A failed acquisition range invalidates the archive crossing it. Run `python scripts/e2e_sevenz.py --binary PATH`, adding `--native` for the FAT32 and 7-Zip comparison.
