# Hosted VMDK extent references

The 96 MiB guest comes from the Windows fixed VHDX after seven actual NTFS deletions. Windows measured the physical guest before it was converted or sliced. For the portable sparse case, the logical source was split at 16 MiB and 48 MiB. QEMU encoded each slice as a twoGbMaxExtentSparse component. The three files in this directory are those component files compressed with XZ. A descriptor assembles them in source order. QEMU independently compares the assembled guest with the original Windows image. The descriptor uses a seven-digit CID, as emitted by QEMU when the high nibble is zero.

The portable flat tests use the same original disk. One maps the whole disk. Another cuts it at the fourth of seven deleted MFT records, stores logical data at nonzero physical offsets in two files, reuses disjoint ranges of one file and describes a verified zero range explicitly. The filenames contain spaces and the files are supplied in reverse order. Every trial compares the entire guest byte by byte, independently checks the Windows SHA-256 for each MiB and the full disk, and recovers HTML, JSON, RTF, XML, PNG, ZIP and gzip against their original bytes and digests.

Run the portable checks with `python scripts/e2e_vmdk_split.py --binary PATH`. Add `--independent` with QEMU installed to compare supported layouts and generate three further images with QEMU. The compact inputs generate a single extent for each of those three QEMU layouts. The identity of the bytes in otherwise valid, wrong flat backing files requires an independent original hash.
