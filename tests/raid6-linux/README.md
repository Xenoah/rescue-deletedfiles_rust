# Linux MD RAID6 の実配列と復元結果

Linux 6.12.107 の隔離したQEMUゲストで、mdadm 4.4を使って5台のディスクに14種類の配列を作成しました。メタデータは1.2、チャンク16 KiB、データ開始位置1 MiB、メンバーの使用長4 MiB、論理ディスク長12 MiBです。ext4をマウントしてBMP、FLAC、GIF、JPEG、PDF、PNG、SQLite、WAV、WebP、ZIPを書き込み、読み戻してから削除しました。各配置で別々に作成・削除した計140件です。

`guest-init.sh` はディスク作成時のゲスト用起動スクリプトです。空の仮想ディスク5台と、カーネルの読取結果を保存する6台目のディスクを使います。各ディレクトリの `guest.txt.gz` は実行ログ、`a.raw.xz` ～ `e.raw.xz` は停止後の全メンバー、`logical.raw.xz` はLinux MDが停止直前に読み出した論理ディスクです。ファイルごとのハッシュと位置は [manifest.json](manifest.json) にあります。

停止済みメンバーの使い捨てオーバーレイを用いて、別のLinuxゲストで全10通りの2台欠損を再現しました。各組み合わせを `mdadm --assemble --readonly --run` で起動し、カーネルが報告した欠損数2、読み取り専用状態、論理ディスク全体のSHA-256を確認しました。14配置×10通りのログは各ディレクトリの `degraded.txt.gz` にあります。元の5台のハッシュも終了後に再照合しています。

```sh
python scripts/e2e_raid6_layouts.py --binary /path/to/rescue
python scripts/e2e_raid6_layouts.py --binary /path/to/rescue --native
```

ポータブル試験は各配置で全台あり、1台欠損の5通り、2台欠損の10通りを試し、2回転分にわたる非ゼロのデータを照合します。2台欠損での削除ファイル復元は全配置・全10形式で原本の全バイトとSHA-256を比較します。3台欠損とパリティ矛盾、2台欠損時の追加破損を検証します。一部の配置では、メンバー取得マップの局所エラー、論理順を取り違えた場合の誤ったデータも試します。[ポータブル試験結果](../../docs/raid6-layout-results.json)

Linuxの追加試験ではmdadmで全メンバーのUUIDを照合し、各配置を2台欠損としてRescueで取得した論理RAW全体をLinuxカーネルの原本と比較します。その後、削除前の位置情報を渡さずに内容検索を行い、10形式の全バイトとSHA-256を再照合します。元のディスク作成と独立照合にLinux MD・mdadm・e2fsprogsを使用しました。Rescueでの構成ファイルの読み取り・復元にはこれらの外部ツールは不要です。[Linuxでの照合結果](../../docs/raid6-layout-native.json)

公開版v1.38.0は末尾固定P/Qで同じ原本10件を復元し、他の13配置を拒否しました。コントローラー独自のメタデータ、DDFコンテナー、リシェイプ中に新旧の位置が混在する配列はこの試験の範囲外です。[旧版との比較](public-v1.38-linux.json)
