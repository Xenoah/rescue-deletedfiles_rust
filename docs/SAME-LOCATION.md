# 元の場所への復元と名前の衝突

alpha.8で同じディスクへの保存を追加。GUI・CLI・MCPで共通の処理を使う。

| 設定・状況 | 動作 |
| --- | --- |
| 元の場所へ戻す | 入力の管理情報を再探索し、確認した相対パスをマウント先へ戻す |
| フォルダーに保存 | 確認した階層を保存先に再現。不明な階層はファイル名だけで保存 |
| 同名ファイル／ZIP | 既定は `資料 (復元 1).pdf`。次は2、3…と増やし、既存ファイルを残す |
| スキップ | 同名ファイルを保存せず、結果を `skipped` として返す |
| 同名フォルダー | 中の既存ファイルを残して統合する |
| ファイルがフォルダー名を塞ぐ | 復元側フォルダーに連番を付ける。スキップ設定ならその配下を保存しない |
| 大文字・小文字だけが違う | Linuxでも衝突として扱う |
| 元のパスが不明・推定 | 元の場所へは保存しない。指定フォルダーへの保存を利用する |
| 深い・長いパス | 相対64階層／保存先込み3,000バイトまで。指定フォルダーでは警告付きで平坦化、元の場所では変更を案内 |

スキャン時は元ディスクに作業フォルダーやセッションを作らない。GUIの任意のセッション保存先が空欄、または同じ媒体なら結果をメモリーに保持する。MCPも同じ媒体の作業先では保存しない。

復元前に選択した全ファイルを読み出し、配置と入力の識別情報を再検証する。選択データは合計512 MiBまで。超過・確保失敗は出力作成前に停止する。読み出しが完了してから通常のファイル作成を行うため、ハードリンク非対応のFAT/exFATの出力にも保存できる。

同じディスクへの保存は未選択の削除データを上書きする可能性がある。別ディスクを使う選択肢も残す。入力デバイスへの直接の書き込み・ファイルシステムの修復は行わず、復元先のマウント済みファイルシステムへ新しいファイルを作成する。

元ボリュームはWindowsのvolume extent、Linuxのmountinfoとsysfsの区画情報、macOSのdiskutilから特定する。特定できない場合やイメージではルートを指定できる。保存済みJSONの名前・パス・サイズ・配置は信頼せず、読み直した管理情報を使う。FAT32の削除名は推定扱いのため、元の場所ではなく指定フォルダーへ保存する。PNG carvingにも元のパスはない。

MCPは明示した出力ルートの範囲を維持する。元ボリューム全体を許可する必要はなく、例えばDocumentsだけを許可できる。既存のルート・保存先をハンドルで固定し、差替え・範囲外へのリンクによる逸脱を拒否する。

## CLI

```powershell
# 間違って削除したPDFを、セッションを保存せずスキャンして戻す
rescue restore --source C: --name report.pdf --original --json

# 保存済みのスキャンから選択。既存ファイルは残す
rescue recover --session scan.json --id mft-123-7 --original --collision keep-both --json

# イメージの元ボリュームを明示する。全ディスクなら --volume-root 1=E:\ の形式
rescue recover --session scan.json --all --original --volume-root E:\ --json

# 512 MiBを超えるジョブは別の物理ディスクへの従来のストリーミングも使える
rescue recover --session scan.json --all --destination E:\Recovered --stream --json
```

`restore`の`--name`は完全なファイル名の大文字・小文字を無視した一致。複数回指定できる。同名が複数あればすべて対象となる。GUIならスキャン結果で個別に選択できる。

## MCP

```json
{"name":"recover_files","arguments":{"session_id":"...","ids":["mft-123-7"],"output_format":"original","collision":"keep_both","request_id":"restore-pdf"}}
```

`volume_roots: [{"partition":1,"path":"E:\\"}]`でマッピングを明示できる。通常保存・ZIPには`destination`が必要。`original`は`destination`を必要としない。`skip`は成功したスキップとしてCLI終了コード0／MCPジョブ完了で返す。

## 検証

`scripts/e2e_restore.py`は合成NTFSから実コーパスのPDFと36ファイルを復元し、既存保護、フォルダー統合、大小文字、リンク、JSON改変、上限、ZIP CRC、MCPの範囲制限を検証する。[ローカル記録](restore-results.json)を参照。

`scripts/e2e_restore_native.py`はCIごとに新規仮想媒体を作り、WindowsのNTFS／Linux・macOSのexFATで実際にPDFを作成・削除し、CLI・MCPから同じボリュームの元の場所へ戻す。既存ホスト媒体は選択・初期化しない。各OSの成功したネイティブ記録をリリースの必須条件とする。

全選択データの事前読出しはマウント中の他プロセスの書込みを止めない。内容のSHA-256は出力の記録であり、削除前の正解と一致する保証ではない。TRIM・上書きで失われたバイトは復元できない。
