# v0.2.0-alpha.5：監査8件の修正

v0.2.0-alpha.4を精査して確認した8件を修正した。発見時の既存テストは成功していたため、
再現条件を新しい回帰テストに組み込んだ。修正前の現象と修正後の期待値を以下に記録する。

| ID | 修正前 | 修正後 | 検証 |
| --- | --- | --- | --- |
| A1 | 探索順で使用中データをディレクトリーと誤認 | 後発の競合を由来ディレクトリー・子孫の候補に反映し、保存を拒否 | 両FS・逆順・子孫の8ケース |
| A2 | MCPの出力検査後の差替えで許可範囲外へ保存 | 許可ルート・出力フォルダーのハンドルを保持し、データとレポートに共用。実体変更は停止 | stdio MCP中のsymlink/junction差替え |
| A3 | 壊れた使用中チェーンの既知範囲を捨てる | 先頭と解析済みの各クラスターを、解析失敗後も保護 | 先頭・途中の2ケース |
| A4 | zlib終端が欠けたPNGも検証済み | 終端、Adler-32、入力消費量、展開長、PLTE・インデックスを検査 | PNG異常系7ケースを追加 |
| A5 | 保存した大きなセッションを読込不可 | 保存・読込の上限を128MiBで統一。超過候補を省略してtruncatedを明示 | 深い階層・7,000ファイルで保存→読込→復元 |
| A6 | 使用中exFATエントリーの解析失敗でも空きを断定 | 解析失敗・未対応critical entry・不正ディレクトリー長を所有関係の不確実性に反映 | checksum・set数・critical entry・directoryの4ケース |
| A7 | GUIの入力表示と復元元セッションが乖離 | セッション読込で表示を同期。入力・方式の変更時に候補を無効化 | 読込・入力変更・方式変更のRustテストとLinux GUI操作 |
| A8 | FAT32にも割当bitmapを根拠として表示 | FAT値、exFAT bitmap、空ファイルの割当なしを区別 | 表示分岐テストとLinux GUI操作 |

A1は、保存時の再探索にも同じ判定を適用する。A3で使用中領域の探索が不完全な場合、
FAT32の非空ファイルを空きと断定せず復元不可にする。exFATはbitmapが空きでも所有関係が不明なら
`allocation_status=unknown`と警告を返す。

A2のファイル操作は検証済みのディレクトリーハンドルを使う。パス文字列だけで許可ルートを照合し直す方式には戻さない。
フォルダーの実体が変化した場合は`DESTINATION_CHANGED`を返す。Windowsがハンドルのあるディレクトリーの移動自体を
拒否する場合も、許可範囲外へ出力しないことをテストする。

A4の「形式検証済み」は削除前の内容との一致を保証しない。補助テキスト・ICCの意味の検証、
APNG・断片化PNGの再構成は引き続き対象外。

A5は全候補を無制限に保持する方式ではない。保持できなかった候補数と制限到達を記録し、保存済みの途中結果を
読み込める状態で返す。通常の上限内のセッションは引き続きv1〜v4を読み込む。

再実行：

```bash
cargo test --workspace --locked --offline
python scripts/e2e_audit.py --binary target/debug/rescue.exe
python scripts/e2e_carve.py --binary target/debug/rescue.exe
```

Linuxでは実行ファイルを`target/debug/rescue`にする。新しい監査回帰16ケースと強化したPNG30ケースを、
Windows/LinuxのdebugおよびWindows releaseのCIに組み込んだ。Windows GUIの実操作とLinux/Xvfbでの操作は区別して記録する。
公開成果物の検証記録は[VALIDATION.md](VALIDATION.md)を参照。
