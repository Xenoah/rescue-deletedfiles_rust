# v1.0.0 の対応範囲

既存リンクとの互換性のためファイル名は `ALPHA.md` のままです。実装の上限と対応プロファイルを記載します。

Quickは物理ディスク・ボリューム・RAWイメージを読み取り専用で開きます。MBR／EBR／GPTの境界を検証し、NTFS・FAT32・exFATの各パーティションを探索します。GPTはヘッダーと配列のCRC、主・副の整合性を確認します。一方が壊れた場合は有効な方を警告付きで使い、修復は行いません。
Carvingはディスク全体または指定した開始以上・終了未満のバイト範囲を読み、PNG/JPEG/PDF/ZIP/Office/MP4/MOVを探索します。既定は未割当領域の候補を選別し、割当が不明な場合は理由を表示して検索します。全領域も明示選択できます。[範囲の詳細](ALLOCATION_SCOPE.md)。

Windowsは`\\.\PhysicalDriveN`、`\\.\D:`、Volume GUID、Linuxはブロックデバイス、macOSは`/dev/[r]diskN[sM]`を受け付けます。GUIはディスク選択を既定にし、イメージは補助モードです。デバイスにはOSの読取権限が必要です。Windowsは通常権限のGUI/CLIから、明示した要求だけを[一時的な読取補助プロセス](READ_ACCESS.md)へ渡します。解析と保存は通常権限で行います。

## 実装対象

- resident DATA、非圧縮non-resident DATA、正負のrunlist差分、疎領域、未初期化領域。
- LZNT1圧縮（16クラスター単位、512〜4096バイト/クラスター）。圧縮・非圧縮・疎領域の混在。
- resident/non-resident/圧縮ADSを個別候補として列挙し、通常ファイルとして別名保存。
- 削除済みMFTレコードの列挙とUTF-16の名前。親参照のシーケンス番号を照合した階層表示。
- MFT自身のrunlistによる読取、セクターfixup・属性・範囲の検証。
- FAT32の削除エントリー、残存チェーン、1クラスター内のファイル、長いファイル名とチェックサム。
  ミラーFATは参照箇所を比較し、不一致を拒否します。ミラー無効時は指定されたactive FATを使い、理由を記録します。
- exFATのブート領域とバックアップのチェックサム、エントリー集合、upcase表と名前ハッシュ。
  NoFatChainの連続割当、残存チェーン、割当ビットマップ、valid data lengthに対応します。
- FAT32/exFATの使用中・削除済みディレクトリーをたどり、使用中領域との競合を拒否します。
  復元時にはディレクトリーを再探索し、セッションの任意バイト位置を信頼しません。
- 連続配置の静止PNG carving：全チャンクCRC、厳密なzlib終端・Adler-32・展開長、パレット、画素の展開、復元時の構造・全PNGハッシュ照合。
  色形式・ビット深度の各合法な組合せ、Adam7、分割IDATに対応します。
- 8ビットHuffman JPEGの連続配置carving。SOF0／SOF1／SOF2、全MCU・圧縮データの過不足・リスタート・プログレッシブ係数・画素を検証。[具体的な対応と上限](JPEG-CARVING.md)。
- 設定 → スキャン → 選択 → 復元のGUI。保存先とフォルダー／ZIPをスキャン前に設定。
- 既定の詳細ビュー：名前・作成日時・更新日時・種類・サイズ・状態。列の昇降順・幅変更と7種のグループ化。アイコン表示も同じ選択を保持。
- NTFS FILETIME、FAT DOS、exFAT UTCオフセットの日時表示。欠損値や不明なタイムゾーンを推測しない。
- Quickの元パス・深度・拡張子フィルター、PNG・JPEG carvingの開始／終了バイト。CLI/MCPも同じ設定を使用。
- ZIP64保存：作業領域へ復元 → 無圧縮ZIPと結果レポート → CRC・ZIP全体SHA-256 → 上書きなしの公開。取消・失敗時は一時領域を保持。
- Recovery Intelligenceパネル：配置・形式、割当・名前、保存・SHA-256を区別して表示。
- CLI、egui/eframeのGUI、ローカルstdio MCP。
- セッション保存、候補検索、明示したIDの復元、出力SHA-256とJSONレポート。
- 既存ファイルの上書き防止、保存先からのパス逸脱防止、変更されたソースの拒否。

## 制限

- PNGは符号化データ・画素バッファ各64MiB、フィルターを含む展開データ128MiB、65,536チャンクまで。
  検証の読取・展開データ・画素バッファを合計してスキャン全体4GiBまで。
  署名数は最大200万、候補は10万。上限到達は未対応候補またはtruncatedとして記録します。
  APNG・断片再構成は未対応。補助チャンクのCRCは照合しますが、圧縮テキスト・ICCの意味は未検証。
  元の名前・階層・削除状態は不明です。割当は管理情報から確認できる場合に表示します。全領域や割当不明の探索では使用中ファイルや埋込画像も候補になり得ます。
  読取窓・チャンク・画素展開の前後で取消を確認します。単一フレーム展開中は完了を待ちます。
- EFSと、属性リスト自身が追加extentsを必要とする配置は未対応です。ディレクトリー自体のADSは未対応です。
  圧縮単位の指数が4以外、クラスターが4096バイトを超える圧縮も未対応です。
  $MFTの属性リストは、既知の領域から拡張レコードをたどれる場合に対応します。
- RAIDは[RAID.md](RAID.md)のJBOD/0/1/5/6/10配置をメンバーイメージから再構成します。ライブメンバーと入れ子配列は拒否します。消失領域・バックアップブート・残存MFTは[DISCOVERY.md](DISCOVERY.md)のプロファイルに対応します。読取マップ付き取得・再開の対応は[IMAGING.md](IMAGING.md)を参照。
- 最大256パーティション、GPT配列16MiB・4096エントリー、EBRチェーン128まで。重複・循環・範囲外・主副GPTの不一致・ハイブリッドMBRは拒否します。512/4096セクターのディスクイメージを検証します。未対応パーティションの省略は警告とtruncatedで示します。
- 同じディスクへの保存と元の場所への復元は[保存仕様](SAME-LOCATION.md)に従います。選択データは合計512 MiBまで先に読み出します。
- FAT12/16、dual-FATのTexFAT、未知のexFAT revisionは未対応です。
  主・副ブートの書換修復は行いません。検証できるバックアップを明示選択する探索は対応します。
- FATのチェーンが消えた複数クラスターのファイルは復元不可にします。連続配置の推測はまだ行いません。
  既知の先頭クラスター内に収まるファイル、またはexFATのNoFatChainは復元できます。
- FAT32でチェーンが消えた削除ディレクトリーは先頭クラスターだけを調べ、truncatedを付けます。
  削除された短い名前の未知の先頭文字を「?」、削除LFNの順序復元を推定として示します。
  LFNのUTF-16は対応済みですが、非ASCII短名のOEMコードページ選択は未対応です。
- 出力は確認した元の名前と階層で保存し、同名は連番またはスキップ。同名フォルダーは統合します。
- 通常の復元・ZIP保存にハードリンクは不要です。大容量向け --stream は別媒体とハードリンク対応媒体を使用します。
  非対応の場合はエラーと.partialファイルを残し、完了扱いしません。
- [SQLite索引](INDEX.md)はQuick・Carving・消失領域・残存MFTをチェックポイントから再開できます。ソースと設定を照合し、選択IDを保持します。イメージ取得は読取マップから再開します。
- GUIは日本語表示、パス入力、各OSのファイル選択、検索・選択・復元・取消に対応します。
  英語へ切替可能で、PNG/JPEG/制限付きテキストの[隔離プレビュー](PREVIEW.md)を提供します。PDF/Officeプレビューは後続範囲です。各OSの日本語フォントを使い、フォントを再配布しません。
- 従来のメモリー内スキャンは最大200万レコード（FATでは32バイトのディレクトリースロット）、10万候補まで。索引スキャンは最大1,000万候補で、ページは最大1,000件/32 MiBです。
  FATは16,384ディレクトリー、階層64、ディレクトリー64MiB、チェーン1,048,576クラスター、
  解析全体で200万クラスター訪問に制限します。上限到達はtruncatedまたはRESOURCE_LIMITで示します。
  FATの総レコード数は探索完了前には不明で、total_records=0です。
- 従来のJSONスキャンでは、通常ボリュームイメージのQuickはschema_version=3、Carvingは6（filesystem=raw、従来のPNGセッションは4）、デバイスQuickとパーティション集合は5を生成します。
  消失領域・残存MFTは8を生成します。v1〜v8を読み込めます。パーティションのIDは`pN:`、元パスは`PN/`を付け、境界と各ボリュームの指紋を保存します。復元時は表を再解析して照合し、JSONの任意オフセットを信頼しません。PNG／JPEGのrecordはバイトオフセット、
  record_sha256は画像全体のSHA-256です。Carvingのscanned_records/total_recordsはバイト数、
  invalid_recordsは検証未通過の形式署名数です。進捗APIはunit=bytesを付けて区別します。
- 従来のJSONセッションは最大128MiB。保存・読込の上限は共通で、候補とパスの予算超過は省略数とtruncatedを記録します。
  索引モードはSQLiteへ候補を逐次保存します。1,000万候補の実GUI計測は[性能記録](PERFORMANCE-v1.md)を参照してください。
- MCPは同時に1ジョブ、最大32ジョブ・4セッション。再起動するとプロセス内の履歴は消えます。
  保存済み索引はopen_sessionで作業領域内から開けます。元ソースも起動時の許可リストに含まれている必要があります。
- MCPは許可ルートと選択した出力フォルダーをハンドルで保持し、データとレポートを同じフォルダーへ保存します。
  保存先の実体が変わった場合はDESTINATION_CHANGEDで停止します。
- ソースの照合は容量、更新日時（イメージ）またはデバイス識別・セクターサイズ、3か所のサンプル、元メタデータの再検証です。
  外部プロセスによる巧妙な同時変更を完全に検出する機能ではありません。不変のコピーを使ってください。
- NTFSは$Bitmapの現在の割当を参考情報として表示します。Quickで列挙する任意形式の内容検証は行いません。FAT32は使用中エントリー、
  exFATは割当ビットマップと使用中ファイルの範囲で競合を確認します。
  使用中ファイルをディレクトリーとして参照する破損も拒否します。使用中領域の探索が不完全なら
  exFATの割当状態はunknownとして警告し、FAT32の空きクラスターも不確実なら復元不可にします。FAT32の残存割当は未参照と空き領域を区別します。
  「completed」は保存完了を示し、
  削除前の内容との一致を保証しません。サンプルハッシュや出力ハッシュも同じ制限があります。

## 検証方法

    cargo test --workspace --locked
    cargo build --workspace --locked
    python scripts/e2e.py --binary target/debug/rescue.exe
    python scripts/e2e_streams.py --binary target/debug/rescue.exe
    python scripts/e2e_fat.py --binary target/debug/rescue.exe
    python scripts/e2e_carve.py --binary target/debug/rescue.exe
    python scripts/e2e_jpeg.py --binary target/debug/rescue.exe
    python scripts/e2e_audit.py --binary target/debug/rescue.exe

Linuxでは最後の実行ファイル名をrescueにします。
合成イメージと正解データから、バイト一致、元イメージの無変更、CLI/MCPの同一結果、
不正レコード、保存先制約を確認します。実利用データや実デバイスはテストで変更しません。

Windowsビルドと同OS上のテストはGitHub Actionsで行います。
LinuxでのビルドやWindowsへの型検査は、Windows実行時の検証とは区別します。
Windows GUIはUIAとネイティブキー入力を専用試験で確認します。手動操作・実IME/読み上げ製品・実SSD/HDDの一般的復元率は未評価です。UFS Explorer/DMDEとの固定3イメージの実比較は[比較記録](COMPARISON-v1.md)で公開し、FAT32の未達を含めて示します。
Windows x64はVCランタイム静的リンク、Linux x64はglibc 2.35以降、macOS x64/arm64は13以降。各インストール版・ポータブル版を配布します。発行者署名はなく、macOSはアドホック署名のみで未公証です。詳細は[INSTALL.md](INSTALL.md)。

## alpha.10 文書・動画と配置

PDF・ZIP/ZIP64・DOCX/XLSX/PPTX・MP4/MOVの連続配置carvingを追加。[形式別の制限](DOCUMENT-CARVING.md)。画像の画素検証と、文書/動画の構造検証を区別します。
新形式のセッションは7、既存PNG/JPEGのみは6。入力ラベル、固定操作欄、折り返し、Ctrl/Command+F、最小720×520を追加。[UIの規則](UI_GUIDELINES.md)。

## alpha.11 イメージ取得

読取専用取得、複数パス、読取マップ、強制終了後の再開、欠損の復元処理への伝播を追加。GUI/CLI/MCPで同じ処理を使う。対応と上限は [IMAGING.md](IMAGING.md)。取得と元の場所への復元は別操作で、物理元媒体の取得先は別媒体を使う。

## alpha.12 NTFS拡張

属性リスト、分割MFT、現在の割当、同一データの別名に対応。[詳細と上限](NTFS-EXTENTS.md)。割当競合を含むNTFSの保存は警告付きとし、完全性の証明にしない。
