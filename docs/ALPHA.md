# v0.2.0-alpha.5 の対応範囲

QuickはNTFS・FAT32・exFATボリュームのRAWイメージ専用で、パーティション先頭をbyte 0に置きます。
Carvingは通常ファイルのイメージ全体からPNGを探索し、GPT/MBR等は解釈しません。実デバイスはまだ受け付けません。

## 実装対象

- resident DATA、非圧縮non-resident DATA、正負のrunlist差分、疎領域、未初期化領域。
- LZNT1圧縮（16クラスター単位、512〜4096バイト/クラスター）。圧縮・非圧縮・疎領域の混在。
- resident/non-resident/圧縮ADSを個別候補として列挙し、通常ファイルとして別名保存。
- 削除済みMFTレコードの列挙とUTF-16の名前。親参照のシーケンス番号を照合した階層表示。
- MFT自身のrunlistによる読取、セクターfixup・属性・範囲の検証。
- FAT32の削除エントリー、残存チェーン、1クラスター内のファイル、長いファイル名とチェックサム。
  ミラーFATは参照箇所を比較し、不一致を拒否します。ミラー無効時は指定されたactive FATを使い、理由を記録します。
- exFATのブート領域とバックアップのチェックサム、エントリー集合、upcase表と名前ハッシュ。
  NoFatChainの連続割当、残存チェーン、割当ビットマップ、valid data lengthに対応します。
- FAT32/exFATの使用中・削除済みディレクトリーをたどり、使用中領域との競合を拒否します。
  復元時にはディレクトリーを再探索し、セッションの任意バイト位置を信頼しません。
- 連続配置の静止PNG carving：全チャンクCRC、厳密なzlib終端・Adler-32・展開長、パレット、画素の展開、復元時の構造・全PNGハッシュ照合。
  色形式・ビット深度の各合法な組合せ、Adam7、分割IDATに対応します。
- Recovery Intelligenceパネル：配置・形式、割当・名前、保存・SHA-256を区別して表示。
- CLI、egui/eframeのGUI、ローカルstdio MCP。
- セッション保存、候補検索、明示したIDの復元、出力SHA-256とJSONレポート。
- 既存ファイルの上書き防止、保存先からのパス逸脱防止、変更されたソースの拒否。

## 制限

- PNGは符号化データ・画素バッファ各64MiB、フィルターを含む展開データ128MiB、65,536チャンクまで。
  検証の読取・展開データ・画素バッファを合計してスキャン全体4GiBまで。
  署名数は最大200万、候補は10万。上限到達は未対応候補またはtruncatedとして記録します。
  APNG・断片再構成は未対応。補助チャンクのCRCは照合しますが、圧縮テキスト・ICCの意味は未検証。
  元の名前・階層・割当・削除状態は不明で、使用中ファイルや埋込画像も候補になります。
  読取窓・チャンク・画素展開の前後で取消を確認します。単一フレーム展開中は完了を待ちます。
- EFS、属性リストの追加extentsは未対応です。ディレクトリー自体のADSは未対応です。
  圧縮単位の指数が4以外、クラスターが4096バイトを超える圧縮も未対応です。
  $MFT自体が属性リストを必要とする場合は、この版ではスキャンを開始できません。
- PNG以外のcarving、RAID、デバイス読取、イメージ取得、破損領域探索は後続フェーズです。
- FAT12/16、dual-FATのTexFAT、未知のexFAT revisionは未対応です。
  主・副ブートが不一致／チェックサム不正の場合の修復・代替探索も未対応です。
- FATのチェーンが消えた複数クラスターのファイルは復元不可にします。連続配置の推測はまだ行いません。
  既知の先頭クラスター内に収まるファイル、またはexFATのNoFatChainは復元できます。
- FAT32でチェーンが消えた削除ディレクトリーは先頭クラスターだけを調べ、truncatedを付けます。
  削除された短い名前の未知の先頭文字を「?」、削除LFNの順序復元を推定として示します。
  LFNのUTF-16は対応済みですが、非ASCII短名のOEMコードページ選択は未対応です。
- 出力は1フォルダーにUUID付きの名前で保存します。元の階層は候補情報に保持します。
- 出力の公開にハードリンクを使うため、保存先はNTFS等のハードリンク対応媒体が必要です。
  非対応の場合はエラーと.partialファイルを残し、完了扱いしません。
- 途中結果は保存できますが、チェックポイントからの継続は未対応です。再スキャンが必要です。
- GUIは日本語表示、パス入力、Windowsのファイル選択、検索・選択・復元・取消に対応します。
  プレビューと英語表示は未実装です。Windowsの日本語フォントを使い、フォントを再配布しません。
- 最大200万レコード（FATでは32バイトのディレクトリースロット）、10万候補まで。
  FATは16,384ディレクトリー、階層64、ディレクトリー64MiB、チェーン1,048,576クラスター、
  解析全体で200万クラスター訪問に制限します。上限到達はtruncatedまたはRESOURCE_LIMITで示します。
  FATの総レコード数は探索完了前には不明で、total_records=0です。
- Quickのセッションはschema_version=3、Carvingは4（filesystem=raw）を生成します。
  v1〜v4を読み込めます。以前の版はv4を読めません。PNGのrecordはバイトオフセット、
  record_sha256はPNG全体のSHA-256です。Carvingのscanned_records/total_recordsはバイト数、
  invalid_recordsは検証未通過のPNG署名数です。進捗APIはunit=bytesを付けて区別します。
- セッションはJSON、最大128MiB。保存・読込の上限は共通で、候補とパスの予算超過は省略数とtruncatedを記録します。
  全候補を保持する大容量索引・メモリ目標の達成は未検証です。
- MCPは同時に1ジョブ、最大32ジョブ・4セッション。再起動するとプロセス内の履歴は消えます。
  サーバーは保存済みの任意セッションを読み込まず、今回スキャンした許可済みソースだけを扱います。
- MCPは許可ルートと選択した出力フォルダーをハンドルで保持し、データとレポートを同じフォルダーへ保存します。
  保存先の実体が変わった場合はDESTINATION_CHANGEDで停止します。
- ソースの照合は容量、更新日時、3か所のサンプル、元メタデータの再検証です。
  外部プロセスによる巧妙な同時変更を完全に検出する機能ではありません。不変のコピーを使ってください。
- NTFSの$Bitmapによる割当競合とファイル形式検証は未実装です。FAT32は使用中エントリー、
  exFATは割当ビットマップと使用中ファイルの範囲で競合を確認します。
  使用中ファイルをディレクトリーとして参照する破損も拒否します。使用中領域の探索が不完全なら
  exFATの割当状態はunknownとして警告し、FAT32の空きクラスターも不確実なら復元不可にします。FAT32の残存割当は未参照と空き領域を区別します。
  「completed」は保存完了を示し、
  削除前の内容との一致を保証しません。サンプルハッシュや出力ハッシュも同じ制限があります。

## 検証方法

    cargo test --workspace --locked
    cargo build --workspace --locked
    python scripts/e2e.py --binary target/debug/rescue.exe
    python scripts/e2e_streams.py --binary target/debug/rescue.exe
    python scripts/e2e_fat.py --binary target/debug/rescue.exe
    python scripts/e2e_carve.py --binary target/debug/rescue.exe
    python scripts/e2e_audit.py --binary target/debug/rescue.exe

Linuxでは最後の実行ファイル名をrescueにします。
合成イメージと正解データから、バイト一致、元イメージの無変更、CLI/MCPの同一結果、
不正レコード、保存先制約を確認します。実利用データや実デバイスはテストで変更しません。

Windowsビルドと同OS上のテストはGitHub Actionsで行います。
LinuxでのビルドやWindowsへの型検査は、Windows実行時の検証とは区別します。
Windows GUIの手動操作、アクセシビリティ、実ディスク、有料製品との比較は別途検証が必要です。
Windows x64用で、Microsoft Visual C++ v14 x64ランタイムが必要です。未署名のプレリリースとして配布します。
