# Rescue v1.7.0

削除されたファイルの管理情報が失われたときに、RTF・XML・MP3・FLAC・TIFFを内容から検索できるようになりました。GUI、CLI、MCPの通常検索と索引検索で利用できます。

| 形式 | 読み取る範囲 |
| --- | --- |
| RTF | RTF 1文書の開始から、対応する最後の閉じ波括弧まで。エスケープ、入れ子、長さ付きのバイナリデータを解釈 |
| XML | XML宣言のあるUTF-8のXML 1.0。先頭のBOMを保持し、ルート要素の終端までを検証。8 MiBまで。DTD、ルート要素より後のコメントや改行は対象外 |
| MP3 | XingまたはInfoにフレーム数とバイト数が記録されたLayer IIIストリーム。先頭の対応ID3v2タグを含め、全フレームの長さを照合。末尾の別タグは対象外 |
| FLAC | STREAMINFOに総サンプル数があり、フレームが8・12・16・20・24ビットの深度を明示するストリーム。各フレームを復号し、連番・CRCと、記録がある場合はPCMのMD5を照合 |
| TIFF・BigTIFF | 両バイト順、ストリップ・タイル、複数ページに対応。認識したタグが参照する最後の領域までを保存し、全ページを復号。復号後の合計は128 MiBまで。独自タグ・サブIFDなど範囲を決められない構造は対象外 |

```sh
rescue scan --source disk.raw --mode carve --extension rtf --extension xml --extension mp3 --extension flac --extension tif --work-dir sessions --json
```

## 実証結果

- 5形式それぞれ8パターンを通常・索引検索で復元し、80件すべてで元のバイト列とSHA-256が一致しました。Pandocの文書、異なるXML生成器の出力を含み、音声はFFmpegで復号してPCMを、TIFFはImageMagickで全ページの画素を照合しました。途中切断・長さ不一致・破損など50条件で壊れた範囲を除外しました。
- 同じ35形式・36原本からNTFSの管理情報を消すと、連続配置で30/36件、断片化配置で10/36件が原本と一致しました。v1.6.0ではそれぞれ25/36件・8/36件でした。独立ツールで作成したファイルシステムを含む試験全体では、計1,116回の照合のうち1,005回で原本に一致しました。同じ原本を異なる条件で繰り返し照合した数です。
- Linux GUIで追加5形式を各1件選び、復元したZIPの各ファイルとHTML・CSVのレポートを照合しました。CP932名、破損したexFAT、独自シグネチャ、既知ハッシュとの照合も試験しました。64 MiBのイメージ取得では読み取りを中断した後、再開して原本と照合しました。[GUI実操作の記録](https://github.com/Xenoah/rescue-deletedfiles_rust/blob/v1.7.0/docs/gui-v1.7-results.json)
