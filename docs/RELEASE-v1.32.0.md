# Rescue v1.32.0

親ディスクが残っている差分QCOW2から、指定した時点のディスクをRAWに復元できます。子が書き換えたデータ、子が明示的にゼロにした範囲、親から引き継ぐ範囲を、クラスタまたはサブクラスタ単位で区別します。変換したRAWを通常の復元・検索に使えます。

## 使い方

GUIの「イメージをRAWに変換」で子のQCOW2を選び、親ディスクの欄に直近の親からベースまでを1行ずつ指定します。CLIでの例です。

```sh
rescue import-image --image-type qcow2 --source child.qcow2 \
  --segment middle.qcow2 --segment base.raw --output recovered.raw --json
```

変換前の論理ディスクのSHA-256が分かっている場合は `--raw-sha256`、バイト数が分かっている場合は `--raw-bytes` を追加できます。どちらかが一致しなければ出力を保存しません。GUIの「元ディスクと照合」からも指定できます。単独のQCOW v1・QCOW2にもこの照合を使えます。

## 復元を確認したディスク

| ファイルシステム | QEMUで作成した条件 | 削除ファイルの原本一致 |
| --- | --- | ---: |
| FAT32 | QCOW2 v2、v3、子より短いRAW親、子・中間差分・RAWベースの3段、ZstandardのQCOW2ベースを含む3段 | 5条件 × 7件 |
| ext4 | 拡張L2の子とRAW親、DEFLATE圧縮されたQCOW2ベースを含む3段 | 2条件 × 7件 |
| Windows NTFS | Windowsが7ファイルを削除した実測済みディスクを基にした3段のQCOW2 | 1条件 × 7件 |

8条件でディスク全体の全バイトとSHA-256をQEMUの展開結果・元の論理ディスクと照合しました。各RAWから削除ファイルを通常・索引付きの両方で復元し、56件すべての全バイトとSHA-256が原本に一致しました。3段の参照イメージでは、QEMUの割当マップでも実際に3層すべてからデータが読み出されることを確認しました。[測定結果](https://github.com/Xenoah/rescue-deletedfiles_rust/blob/v1.32.0/docs/qcow2-backing-results.json) · [QEMU参照イメージ](https://github.com/Xenoah/rescue-deletedfiles_rust/tree/v1.32.0/tests/qcow2-backing)

親の不足・順序違い、破損した割当範囲、既知の原本との不一致など26例で出力を拒否しました。名前も形式も正しい別の親に入れ替えると、展開自体は可能でもディスクの内容が変わります。このケースで元のSHA-256を指定すると保存を拒否することを確認しました。FAT32で実際に削除した7形式は、単独のQCOW v1とQCOW2でも既知のサイズ・SHA-256を指定して復元しました。

LinuxのGUIでは、親2ファイルと既知のSHA-256・バイト数を入力し、変換結果がスキャン元に選択されることを確認しました。そのRAWから7ファイルを原本と照合し、同名の別の親を指定した場合はGUIが出力を拒否しました。GUIの検索・選択・ZIP復元でも7件の全バイトが一致しました。[GUIの実測結果と画面](https://github.com/Xenoah/rescue-deletedfiles_rust/blob/v1.32.0/docs/gui-v1.32-results.json)

Rustテスト96件、Clippy、統合試験90組が通過しました。35形式・36原本の比較試験では、上書きによる消失などを含む1,116条件のうち1,016条件で原本と完全一致し、全条件で期待どおりの結果が得られました。

## 対応範囲と制限

- QCOW2 v2・v3の子と、ヘッダーに形式が明記されたRAWまたはQCOW2の親に対応します。子を含めて最大8ファイルです。親が子より短い場合は、親の論理終端以降をゼロとして扱います。
- ファイル内に記録されたパスやURLは開きません。明示的に選んだ親のファイル名を記録と照合するため、ディレクトリを移動した一式も選べます。親の同一性をファイル名だけで確定できない場合は、既知の論理ディスクのSHA-256で照合してください。
- 暗号化、内部スナップショットの選択、外部データファイル、親形式の記録がないイメージ、ネットワーク上の親はこの読取機能の対象外です。信頼できる構成一式をQEMUなどで完全なRAWに変換できた場合は、そのRAWを復元元に選べます。検証にはQEMUを使いました。対応するチェーンの変換時には外部ツールは不要です。
- 親が失われた場合、そこから継承していたバイトは再現できません。展開後の削除ファイルの復元可否は、ファイルシステムの管理情報やデータが残っている範囲によります。
