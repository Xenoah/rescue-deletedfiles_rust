# 原本の全体ハッシュが残っている35形式の復元試験

v1.21.0候補のLinuxリリースビルドで、リポジトリの35形式・36原本を検証しました。各ファイルの元のバイト数とSHA-256を渡し、8 MiBのテストディスク全域を512バイト間隔で検索しました。連続配置、断片化配置、上書きの各イメージでブートセクターと全MFTレコードを消去しました。

| 保存状態と情報 | 原本と全バイト一致 | 全範囲の探索で一致なし | 検索上限で終了 |
| --- | ---: | ---: | ---: |
| 連続、先頭位置不明 | 36 | 0 | 0 |
| 断片化、先頭位置不明 | 14 | 22 | 0 |
| 断片化、各ファイルの先頭位置が既知 | 16 | 13 | 7 |
| 全ファイルの保存領域を上書き、先頭位置不明 | 0 | 36 | 0 |

連続配置ではプレーンテキスト、CSV、末尾にパディングがあるTARも元の長さどおりに復元しました。先頭位置不明の試験は1ファイルごとに1 GiB、先頭位置既知の試験は512 MiBを検索量の上限としました。断片化時は元の各セクターを1セクターずつ離して配置しています。先頭位置既知の試験は、連続する1領域または2領域を照合します。同じ内容が複数の場所にある場合も、書き出した全バイトとSHA-256を照合しました。

これは保存状態を制御したイメージ試験です。各原本の内容・形式は比較用コーパスから取得しました。実際に削除したFAT12・16・32の試験は別途21件で行っています。[全ファイルのサイズ・照合結果・検索量](whole-hash-corpus-v1.21.json) · [FATでの実削除](whole-hash-v1.21-results.json)

```sh
python scripts/e2e_whole_hash_corpus.py --binary /path/to/rescue --output results.json
```
