# exFATの大文字変換表が壊れている場合

通常は大文字変換表のチェックサム・内容が不正なら、管理情報による探索を停止します。表の内容だけが壊れていて、配置・割当情報を検証できる場合に限り、利用者が明示的に探索を続けられます。

GUIの詳細設定で「exFATの大文字変換表が壊れていても探索する」を選びます。CLIは `scan --exfat-allow-damaged-upcase`、MCPの `start_scan` は `exfat_allow_damaged_upcase: true` です。既定は無効で、carvingでは指定できません。

継続するのは、読み取れた大文字変換表のチェックサム不一致または展開内容の不正だけです。表自体が見つからない・重複する・読めない、サイズやFATチェーンが不正、割当ビットマップが欠ける、といった条件は引き続き拒否します。ルート・ビットマップ・変換表のクラスタが重複したり、空きと記録されている場合も拒否します。

各ファイルはエントリ集合のチェックサム、UTF-16名、ストリーム・長さ、配置とライブファイルとの所有競合を従来どおり検証します。変換表を使う名前ハッシュの検証はできないため、候補と復元レポートに `EXFAT_UPCASE_UNVERIFIED` を記録し、元のパスを未検証として扱います。Unicode標準の大文字変換で代用はしません。変換表が正常なら、オプションを指定していても名前ハッシュを検証します。

この設定はセッション・索引・再開点へ保存され、復元・プレビューでも同じ条件で管理情報を読み直します。設定が食い違う再開点は拒否します。セッションはスキーマ11を使い、以前の版による誤解釈を防ぎます。CP932も同時に指定できます。

HTML/CSV/ZIPにも名前の不確実性を残します。復元ファイルのSHA-256は保存した内容の識別値であり、削除前の内容や元パスの正しさの証明には別の正解データが必要です。

検証は所有する合成exFATイメージを使い、破損表からの72出力のバイト一致、管理情報の拒否条件、CLI/MCP・JSON/索引・MBR/GPT・プレビュー・実プロセス強制終了後の再開を確認します。物理故障SDカードの復旧率を示すものではありません。
