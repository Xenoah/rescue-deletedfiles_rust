# Rescue v1.42.0

QCOW2ファイルに保存された内部スナップショットを一覧し、指定した時点のディスクをRAWに取り出せます。ディスクを拡張した後も、以前の世代は当時の容量で書き出します。保存したVMメモリがある場合は、それがゲストディスクに混入しないことを確認します。

```sh
rescue qcow2-snapshots --source machine.qcow2 --json
rescue import-image --source machine.qcow2 --image-type qcow2 --qcow2-snapshot-id 4 --output saved.raw --json
rescue scan --source saved.raw --work-dir scan --json
```

一覧のIDを2行目に指定します。名前が一意なら `--qcow2-snapshot-name` でも選べます。選択を省略すると現在のディスクを出力します。削除前のディスクの長さやSHA-256を記録してある場合は、`--raw-bytes` と `--raw-sha256` で確認できます。GUIでは「イメージをRAWに変換」でQCOWを開き、「スナップショット一覧」から世代を選びます。

## 実際に削除したファイルでの検証

Windowsで作成したNTFS、mtoolsで削除したFAT32、debugfsで削除したext4の履歴をQEMUで保存しました。8構成すべてで、43の保存世代をID・名前の両方で書き出し、元のゲストディスクと全バイト・SHA-256を照合しました。8つの現在ディスクには保存後に別の書き込みがあり、こちらも独立に照合しました。[原本と再現手順](../tests/qcow2-snapshots/README.md) · [世代ごとの照合結果](qcow2-snapshot-native-results.json)

| 構成 | 保存世代 | 確認した条件 |
| --- | ---: | --- |
| NTFSのv2、Zstandard圧縮NTFS、FAT32のv3 | 9 | 保存世代間で共有するL2表、圧縮クラスタ、削除後の実ファイル |
| ext4のv3と拡張L2 | 16 | 各8世代、削除件数が0件から7件に増える過程 |
| 2度拡張したNTFS | 5 | 96、104、112 MiBのディスク長、追加領域の末尾、拡張前のL1表 |
| メモリを含むNTFSおよび拡張L2のext4 | 13 | 停止状態のQEMUで保存・再読込した2台。各207,044バイトのVM状態をディスク出力から除外 |

各構成の最終保存世代で削除済み7件を復元し、延べ56件・異なる原本13件が、通常検索でも索引付き検索でも原本のバイト列とSHA-256に一致しました。QEMU 6.2と10.0.13の両方で保存ディスクを独立に読み戻しました。ext4ではThe Sleuth Kitで各世代の削除履歴を確認し、延べ91件の内容を原本に照合しました。

QEMU 10の `qemu-img convert -l` は、容量変更前のスナップショットを現在のディスク長までゼロで埋める場合があります。実測では、元のディスク長までが全バイト一致し、その後の追加領域はすべてゼロでした。Rescueの出力はスナップショットに記録された当時の長さでした。

Linux GUIでは一覧から `RAM-history` を選んで96 MiBのディスクに変換し、スキャン元として選択されたことを確認しました。そこから削除済み7件をZIPに復元し、展開した106,654バイトを原本に照合しました。存在しないIDを入力した場合は出力ファイルが作成されませんでした。[GUIの記録と12枚の画面](gui-v1.42-results.json)

Rustテスト96件、Clippy、Linuxリリース実行ファイルの統合試験101組が通過しました。35形式・36原本の回帰試験は1,116条件が期待結果と一致し、そのうち1,016条件で原本と全バイト一致しました。

## 破損・未対応範囲

- 不明なID・名前、重複するID、曖昧な名前、破損したマッピング表、保存したVMメモリとゲストディスクの重複、原本と異なる論理SHA-256など48条件で出力を拒否しました。構造が正常なゲストデータの1バイトを変更した試験では、元のSHA-256を与えると変更を検出しました。[条件別の結果](qcow2-snapshot-results.json)
- 内蔵機能で扱うのは単独QCOW2 v2/v3です。内部スナップショットを持つ外部親チェーン、暗号化、外部データファイル、dirty/corruptフラグ付きイメージは対象外です。外部親を必要とする場合はすべての参照先を確保し、対応するQEMUで読み出してください。暗号化には鍵が必要です。
- 保存VMメモリは非圧縮の通常クラスタ、または割り当てられた拡張L2サブクラスタで記録されている場合を扱います。VM自体の再開にはQEMUが必要です。最大256スナップショット、ディレクトリ16 MiB、L1表合計64 MiB、メモリ配置を示すL2表合計128 MiBまでです。
- 保存時点ですでに上書き・TRIMされ、他の世代にも元のデータが残っていないファイルは復元できません。ファイルシステムの記録を失った場合は、連続データや既知のハッシュなど利用できる証拠によって復元範囲が変わります。
