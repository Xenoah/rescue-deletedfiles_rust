NTFS: 27 extension/allocation/alias scenarios per platform. Windows additionally deleted an OS-created file with 20 resident ADS and two hard-link names on a new VHD; all 21 resident streams matched through CLI and MCP. Nonresident streams were checked separately with TRIM notifications enabled and disabled: erased descriptors must produce no successful empty files, while retained content must match the original.
Acquisition: CLI/MCP process-kill resume, torn journals, strict gap propagation, source identity and stable map pages; actual read-only native disks acquired byte-exact and 108 files restored. Each native OS also exercised a full owned virtual volume, resumed after releasing its filler file and rejected permission-denied output.
Document/media carving: 69 cases, 23 valid variants, 30 rejected malformed/unsupported conditions and 30 byte-exact CLI/MCP outputs on each exact public CLI.
JPEG carving: 32 synthetic JPEGs plus an embedded thumbnail (33 JPEG candidates) were byte-exact through CLI/MCP; 33 malformed structures/entropy cases were rejected. PNG co-scanning, ranges, aliases, ZIP, collisions and revalidation passed.
The 35 format families / 36 files also passed the 60-case ZIP/date/search/MCP feature suite on each public CLI.
Each exact public CLI additionally passed original-path/collision cases and two actual PDF deletions/restorations to the same newly created mounted virtual volume through CLI and MCP. Session work directories were never created on that source volume.
Observation totals include expected unsupported and data-loss cases; they are not general recovery rates.
Linux additionally tested independent filesystem tools and real mtools FAT32 deletion. Mac signing changes the CLI hash; the original format-results JSON records the pre-signing test, while these published-format JSON files record the actual signed portable bytes.

Whole-disk access uses new read-only loop/VHD/hdiutil devices with synthetic deletion metadata; original-location tests use new writable virtual volumes and actual PDF deletion. These do not test real HDD/SSD recovery, TRIM, paid products, or manual Windows/macOS GUI operation.

FAT12/16 fixed-root, packed-table, partition and CLI/index/MCP recovery matched 60 files per platform. Explicit FAT estimation matched 10 known files and refused corrupt/allocated extents. One deliberately fragmented unknown-format file produced incorrect bytes and remained labelled unverified, never counted exact. Linux also recovered eight actual mtools deletions on FAT12/16.

The seven alpha.16 suites also passed on each exact public CLI: isolated preview, allocation scope, job contract, naming, source identity, raw export and damaged FAT mirrors. Damaged FAT recovery matched 20 outputs; raw export matched two outputs and retained explicit unreadable-range evidence.

The exact public Windows GUI additionally passed UIA Invoke/Value, native SendInput keyboard and installed Microsoft Japanese IME flows under a verified non-elevated, medium-integrity token with administrator membership disabled. All three recovered the two selected Unicode-named files byte-exact, preserving the source. Native Roman-key IME conversion and cancellation passed, and the input layout was restored. Screen-reader product evaluation remains unmeasured.
