# Rescue v1.4.0

VDI仮想ディスクをRAWへ変換できるようになりました。管理情報が失われた媒体では、AVI・Matroska（MKV）・WebM・Ogg・gzipの5形式を新たに検出し、GUI・CLI・MCPから復元できます。

## VirtualBoxのディスクを開く

単独のVDI v1.1に対応します。固定サイズ・可変サイズのどちらも、仮想ディスクの論理順で新規RAWへ書き出します。未割当ブロックはVDI仕様に従いゼロとして扱います。入力の読み込みは内蔵されており、変換用ツールの追加インストールは不要です。

```sh
rescue import-image --source guest.vdi --output guest.raw --json
rescue scan --source guest.raw --work-dir sessions --indexed --json
```

形式は自動判定されます。明示する場合は `--image-type vdi` を指定します。スナップショットの差分VDIや親ディスクを必要とする形式は対象外です。変換中の取消や異常終了では完成パスに途中データを公開しません。既存の出力は保持します。

## 管理情報を使わない復元

| 形式 | 復元単位と確認内容 |
| --- | --- |
| AVI | 単一の標準RIFF。ストリーム数、ヘッダー、映像・音声チャンクの境界。OpenDMLは対象外 |
| MKV・WebM | 長さを記録したEBMLセグメント。DocType、トラック、クラスタ、ブロックのトラック番号とレース境界。長さが未確定のライブ収録は対象外 |
| Ogg | 開始ページから終了ページまでの単一論理ストリーム。全ページのCRC、連番、シリアル、パケットの継続状態を照合。連結時は個別の候補になり、複数ストリームの交互配置は対象外 |
| gzip | 1メンバー単位にDEFLATEを展開し、CRC32と元サイズを照合。続くメンバーは別の候補として扱う。展開サイズの上限は1メンバー128 MiB |

1候補の入力上限は64 MiBです。動画・音声コーデックのデコードや、ディスク上で分断されたファイルの組み立ては行いません。削除情報が残る通常スキャンでは、これまで通りファイル内容の形式を問わず復元できます。

## 実証

| 試験条件 | 照合結果 |
| --- | --- |
| ファイルシステムのないRAWに追加5形式の原本を配置 | 通常・索引の各5件を復元し、元のバイト列とSHA-256に一致。各形式の末尾切断、およびAVIヘッダー、EBMLサイズ、Ogg・gzipのCRCの破損を拒否 |
| 36ファイル・35形式の固定コーパスでNTFSの管理情報を消去 | 連続配置で21/36件、断片化配置で4/36件が原本に一致。v1.3.0の同じ試験では16/36件と3/36件 |
| qemu-imgで作成した固定・可変VDI | 各16 MiBのRAW全体が原本に一致。各ディスクのext4で実際に削除した7ファイル（計14件）の内容も一致 |
| VDIに逆順の物理ブロック・未割当・明示ゼロ・端数の最終ブロックを配置 | 自動判定・形式指定の両方で論理RAWが一致し、それぞれ5ファイルを復元。途中切断、親参照、不正なブロック番号と重複割当を拒否 |
| 読取マップの欠損セクターに隣接したファイル | BMP・GIF・WebP・WAV・SQLiteの5件は、末尾まで読める場合に全バイト一致。同じ5件を末尾1バイトだけ欠損させると、すべて復元不可と判定 |

この数値は固定試験イメージでの実測です。上書き・TRIM後のデータや、任意の実ディスクでの復元率は保証できません。GUIでの選択復元、HTML/CSV、既知ハッシュ照合、読取中断からの再開の記録は[実操作結果](https://github.com/Xenoah/rescue-deletedfiles_rust/blob/v1.4.0/docs/gui-v1.4-results.json)にあります。
