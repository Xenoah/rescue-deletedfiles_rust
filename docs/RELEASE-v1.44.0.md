# Rescue v1.44.0

Linux LVM2の連結・ストライプ配置を読み取り、選んだ論理ボリュームをRAWに書き出せます。グループ内の物理ボリューム（PV）をすべて指定してください。複数のPVはUUIDで識別するため、入力の順番や元のデバイス名が変わっても読み出せます。

```sh
rescue lvm-volumes --source disk-a.pv --segment disk-b.pv --json
rescue import-image --image-type lvm2 --source disk-a.pv --segment disk-b.pv --lvm-volume data --output data.raw --json
rescue scan --source data.raw --work-dir scan --mode carve --json
```

2行目の `data` には一覧に表示された名前またはUUIDを指定します。論理ボリューム全体の記録があれば、`--raw-bytes` と `--raw-sha256` を加えて元の長さ・内容を確かめられます。GUIでは「イメージをRAWに変換」でLVM2と各PVを指定し、「論理ボリューム一覧」から選択します。

## Linuxでの作成・削除・復元

QEMU上のLinux 6.12.107とLVM 2.03.31を使って、2つずつのPVから4つのグループを作成しました。各グループの2つの論理ボリュームをext4でフォーマットし、マウントしてファイルを作成しました。読み戻してから削除し、アンマウント後にLinuxのdevice-mapperから全セクターを別のディスクに保存しました。[原本と検証手順](../tests/lvm2/README.md)

| グループ | 連結配置 | ストライプ幅 | 実際に削除して全体一致したファイル |
| --- | --- | ---: | ---: |
| 各PVにメタデータ1個 | 8 MiB ＋ 8 MiB | 64 KiB | 7件 × 2 |
| 各PVの前方と後方にメタデータ | 3 MiB ＋ 13 MiB | 16 KiB | 7件 × 2 |
| グループ内にメタデータ1個 | メタデータを持たないPVの16 MiB | 4 KiB | 8件 × 2 |
| メタデータがリングの末尾をまたぐ配置 | メタデータを持たないPVの16 MiB | 4 KiB | 8件 × 2 |

8論理ボリュームの各16 MiBが、Linuxの読み出し結果に全バイトとSHA-256で一致しました。通常検索と索引付き検索の両方で、実際に削除した延べ60件が原本と一致しました。原本はGIF・JPEG・PDF・PNG・SQLite・WAV・ZIPの7形式8ファイルです。大きいPNGは4 KiBのストライプを複数またぎます。[論理ボリューム別の照合結果](lvm2-results.json)

Ubuntu 22.04向けLVM 2.03.11とDebianの2.03.31で、`pvck` が取り出した現在のメタデータ8コピーの全バイトを原本と照合しました。リングの末尾をまたぐ実例では、60 KiBのメタデータ領域のオフセット60,416から始まる1,879バイトの記録を読み戻せました。[pvckの独立照合結果](lvm2-native-results.json)

Linux GUIでは2つのPVを指定し、一覧から `rescue_vg/striped` を選んで16 MiBを変換しました。変換後のディスクをGUIでスキャンし、削除済み8件をZIPに復元して、展開した31,236バイトと各ファイルのSHA-256を原本と照合しました。存在しない論理ボリューム名では出力を作成しませんでした。[GUIの記録と12枚の画面](gui-v1.44-results.json)

Rustテスト96件、Clippy、Linuxリリース実行ファイルの統合試験103組が通過しました。既存35形式・36原本による回帰試験では1,116条件が期待結果に一致し、うち1,016条件が原本の全バイトに一致しました。

## 上限と復元できない条件

- PVラベル、メタデータ領域、アクティブなグループ記録のチェックサムを照合します。必要なPVの欠落、コピー間の不一致、ストライプ配置の競合、重複割り当て、範囲外の参照など38条件を検証しました。データ領域だけが変更された場合は元のSHA-256を与えて検出できます。
- 対応するのはグループ全体が通常の連結・ストライプで構成されたLVM2です。指定するのは個々のPV全体のイメージで、上限は32個、メタデータ本文は各4 MiBです。ディスク内のパーティションがPVなら、そのパーティションを切り出して指定してください。
- スナップショット、thin、cache、RAID、ミラー、共有ロック、移動・マージ途中のグループには対応するLinux LVM環境が必要です。暗号化されたPVには鍵と復号済みイメージが必要です。欠落したPV、破損した記録、上書きやTRIMで失われたデータの復元には別のコピーなどが必要です。
