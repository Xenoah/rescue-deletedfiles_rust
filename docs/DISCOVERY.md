# 消失領域とブートの仮想解析（開発中）

ディスクを書き換えず、512バイト境界のNTFS/FAT32/exFATブートを探索します。
サイズ・位置を検査した後、NTFSではMFTのfixup・runlist・先頭配置・ルート参照、
FATではBPB・設定されたバックアップ・予約FAT・ミラー・ルート範囲を照合します。
exFATは12セクターのchecksumとルート内の割当Bitmap/Upcaseの境界も確認します。
ヘッダー1個の一致だけで候補にはしません。

主ブートと同じ幾何情報のバックアップはまとめ、重なる別の解釈は選択候補として残します。
GUIの候補表で形式・開始バイト・サイズ・主/バックアップ・現行領域表との一致・重複を比較し、
1領域を設定へ戻してスキャンします。CLIは`discover`で得たIDを`scan --volume-id ID`へ渡します。
MCPは`discover_volumes`の非同期結果から1つの`region`を`start_scan.recovered_volume`へ渡します。
取消、リクエスト再送、ソース許可範囲を共通のジョブ契約で扱います。

## ブートの扱い

選択したブートの絶対位置・長さ・SHA-256をセッションに保存します。
復元前には範囲の導出と内部構造を再検証します。別のセクターへの差替えや内容の変更は拒否します。
バックアップは幾何情報の解析時にだけ使用し、ファイルの読取バイトには置き換えを適用しません。
元のパーティション表・ブート・MFTを書き直す処理はありません。

失われた領域は現在のマウント先と同じとは限りません。「元の場所」にはルートの明示が必要です。
通常のフォルダー保存とZIP、同名処理、同一媒体での先行読出しは従来どおりです。

## MFTミラー

主MFTレコード0が読めない場合は、ブートが指定するミラーのfixupを検証します。
ミラーのrunlistが主MFTの先頭を指し、元のMFTにあるルート5の所有者・シーケンスが整合する場合に
初期読取へ使用します。その後のレコードは元のrunlistから読み、レコード0以外をミラーから補完しません。
ミラーで全MFTを再生できるとは表示せず、使用した根拠を警告と復元レポートへ残します。

## 上限と検証状況

探索窓は4 MiB、メタデータ照合は1候補8 MiB・全体256 MiB、最大4,096試行・256領域です。
取得マップの欠損は正常なゼロと区別してスキップし、未探索を通知します。
NTFSのセクター数/最終セクター番号の違いは、バックアップ位置とMFTの整合性で確認します。
FAT32のバックアップ位置はBPBの値、exFATは12セクター後を使用します。

ローカルの19条件で、3形式の消失MBR・主ブート破損、偽署名、整数上限、重複領域、
改変セッション、元データ変更、MFTミラー、取消、CLI/MCPの一致を確認しました。
63件の出力は正解データとバイト一致し、元イメージは不変でした。
Windows/Linux/macOSのネイティブ試験と公開パッケージ検証はこの工程の完了時に実施します。
MFT断片・クイックフォーマット後の旧メタデータ探索はこの段階ではまだ開発中です。
