# 等間隔に断片化したファイルの復元試験

原本のバイト数とSHA-256が分かる場合の試験です。復元したファイルの全バイトとSHA-256を原本と照合しました。

## FATで実際に削除した21件

FAT12、FAT16、FAT32にTXT、CSV、HTML、WAV、ZIP、独自形式のバイナリ、同一セクターが繰り返されるデータを各7件書き込みました。各ファイルは3〜10個の領域に分かれています。削除前にmtoolsでファイルを読み出し、物理位置を記録しました。削除後、各ファイルで次の2通りを試し、いずれも21件すべてでファイル内容、SHA-256、全領域の位置が一致しました。

- 先頭位置を指定せず、断片長と断片の先頭間隔を指定。FAT16ではクラスタ境界の起点をデータ領域に合わせました。
- 先頭位置と断片長を指定し、前後10ブロックの範囲で間隔を探索。

クラスタサイズはFAT12・32が512バイト、FAT16が1,024バイトでした。実削除の作成・独立照合にはmtoolsを使用します。復元機能自体は外部ツールを必要としません。[21件のハッシュと削除前の配置](strided-files-v1.23-results.json)

## 35形式・36原本での配置別比較

8 MiBの比較用イメージで先頭のブートセクターと全MFTレコードを消去し、元データを512バイトずつ1セクターおきに配置しました。固定間隔の試験はディスク先頭から512バイト境界を検索し、間隔を探索する試験は各原本の先頭位置を指定しました。

| 状態 | 先頭位置不明、2ブロック間隔を指定 | 先頭位置既知、前後8ブロックまで探索 |
| --- | ---: | ---: |
| 等間隔の断片が残存 | 36/36件一致 | 36/36件一致 |
| 同じ配置の全データ領域をゼロで上書き | 0/36件、全件一致なし | 0/36件、全件一致なし |

どちらの試験も検索上限には達していません。従来の連続・2領域検索では、同じ断片化イメージで先頭位置不明が14/36件、先頭位置既知が16/36件でした。断片の間隔や長さが途中で変わる場合、保存場所を追加で特定する手がかりが必要です。読み取れない領域は照合から除外します。[ファイル別の詳細](strided-corpus-v1.23.json) · [従来の検索結果](WHOLE-HASH-CORPUS.md)

```sh
python scripts/e2e_strided_files.py --binary /path/to/rescue --native
python scripts/e2e_whole_hash_corpus.py --binary /path/to/rescue --regular-strides --output results.json
```
