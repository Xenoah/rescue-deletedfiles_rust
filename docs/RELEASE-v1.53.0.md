# Rescue v1.53.0

Linux MDのRAID5・RAID6はメンバーのRAWイメージを選ぶと、管理情報から配置、順番、個別の開始位置と長さを取得できます。管理情報1.0・1.1・1.2に対応し、RAID5は1台、RAID6は2台まで欠損した構成を読み取れます。論理セクターが4 KiBのメンバーは `--sector-size 4096` を指定してください。

```sh
rescue raid-md --member disk-e.raw --member disk-b.raw --member disk-d.raw \
  --output array.rescue-raid.json --json
rescue scan --source array.rescue-raid.json --mode carve --work-dir scan --json
```

GUIではRAID構成画面にメンバーを入力し、「入力したメンバーからLinux MD構成を読む」を選んでから構成を保存します。実GUIで入力順を逆にし、配置と開始位置・長さを意図的に違えた状態から、正しいDDF N-continue構成、16 KiBストライプ、欠損スロット0・2を読み取りました。GUIが保存した構成はCLIで独立に検出したものと一致しました。検出した構成から10形式をGUIでスキャン・ZIP保存し、全31,604バイトとSHA-256を照合しました。[画面と照合結果](gui-v1.53-results.json)

| Linux実配列での確認 | 結果 |
| --- | --- |
| RAID5・6、管理情報3世代、512バイト・4 KiBのメンバー | 19配列・92メンバー。うち5配列を新規作成 |
| ext4で実際に削除した10形式を、メンバー不足の状態から復元 | 19配列で190件すべて原本の全バイト・SHA-256と一致。うち50件が新規配列 |
| 再構成した論理ディスクとLinux MDの読み出し | 各12 MiB、19組すべて全バイト・SHA-256が一致。通常の内容検索でも190件一致 |
| 同じ配列の1台を取り外して書き込んだ実世代 | イベント17と21の混在を拒否。現世代の3台から変更後の全12 MiBと削除済み10件を復元 |

UUID、世代、役割表、スーパーブロックのチェックサム、領域境界を確認します。管理情報を読み取れないメンバー、混在する世代や配列、同期中、機能フラグ付きのメンバーは拒否します。内部ビットマップや外部メタデータを持つ配列は、対応するLinux MDやコントローラーを別コピーに使用し、読み取り専用で取得した論理RAWを利用してください。すべての入力が過去の同じ世代なら、新しい世代が別に存在するかは判定できません。[対象範囲と原本](../tests/md-superblocks) · [ファイル別の実測](md-superblock-native.json)
