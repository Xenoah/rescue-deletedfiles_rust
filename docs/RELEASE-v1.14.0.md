# Rescue v1.14.0

削除されたAAC-LC録音とTARアーカイブを、ファイルシステムの管理情報が消えた後も内容から検索できます。通常の検索、索引検索、GUI、CLI、MCPで使用できます。

## AAC録音を探す

```sh
rescue scan --source disk.raw --mode carve --extension aac --work-dir audio-scan --json
```

モノラルまたはステレオの非保護ADTSを対象に、3つ以上のフレームの形式・サンプリング周波数・チャンネル構成を照合します。各フレームをAAC-LCデコーダーで展開し、符号化されたチャンネルとフレームの終端を確認します。

ADTSには録音全体の長さが記録されません。同じ設定の録音が隙間なく続くと、ひと続きの候補になります。先頭が上書きされている場合でも、残った部分だけが候補になることがあります。CRC付きADTS、HE-AAC、前後のタグ、断片の並べ替えには対応していません。

## TARの末尾まで取り出す

```sh
rescue scan --source disk.raw --mode carve --extension tar --work-dir tar-scan --json
rescue scan --source disk.raw --mode carve --extension tar --tar-blocking-factor 20 --work-dir gnu-tar-scan --json
```

ustar、GNU、POSIX/PAXのヘッダーを読み、各メンバーのサイズとヘッダーチェックサム、パディング、2個の終端ブロックを検査します。指定がなければ2個目の終端ブロックまでを保存します。作成時のレコード長が分かっている場合、512バイトを単位として指定できます。たとえばGNU tarの標準値は20です。GUIは検索の詳細設定「TARの保存単位」、MCPは `tar_blocking_factor` で設定できます。

## 実ファイルでの検証

| 試験 | 原本と照合した結果 |
| --- | --- |
| ext4で実際に削除したAAC | FFmpegが生成した8～96 kHzの7録音を通常・索引の両方で復元。全14出力でバイト列・SHA-256が一致し、FFmpegが展開したPCM音声も原本と一致 |
| FAT32で実際に削除したTAR | mtoolsで読み戻した後に削除した7アーカイブを、通常・索引の両方で復元。全14出力のバイト列・SHA-256と、格納された各ファイルのSHA-256が一致 |
| TARの形式とレコード長 | 長い名前、Unicode、空ファイル、ディレクトリ、ハードリンク、シンボリックリンクを含む9アーカイブを1・7・20ブロックの条件で照合。MCPでも20ブロックの7原本を復元 |
| GUIでの検索からZIP保存 | FAT32で実際に削除したAAC 7件とTAR 7件を新しく検索し、14件をまとめてZIPに保存。全14件のバイト列とSHA-256、GUIが生成したレポートを照合 |
| 破損時の挙動 | AACの途中で切れたフレームや音声を含まない壊れたブロック、TARのヘッダー・PAX長・ファイル末尾のパディング・終端ブロックの破損では、該当先頭からの復元を拒否 |
