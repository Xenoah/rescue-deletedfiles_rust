# v1.1以降の後続課題台帳

作成日: 2026-11-06 JST。仕様の根拠は [SPEC.md](SPEC.md) の3.3「対象の境界と後続拡張」。

この台帳の課題は、現行SPECで「後続拡張」「v1.0に含めない」とされた範囲です。
[v1.0受入台帳](V1_ACCEPTANCE.md) とは別に管理し、v1.0の達成実績には数えません。

## 共通の完了基準

既存の受入台帳と同じ基準で判定します。コードがあるだけでは完了にしません。

- 正解データ付きケースで、復元したバイトを照合する（SHA-256一致）。
- 異常系（破損・欠損・不正値）を試験し、拒否・停止の理由を記録する。
- Windows・Linux・macOS Intel/ARMの4ネイティブVMで回帰試験を通す。公開パッケージの実物でも検証する。
- 未対応を成功扱いしない。対応できない組合せは、理由付きで対応表と結果に記録する。
- 構造検証や出力ハッシュは、削除前の内容と一致する証明としては表示しない。

状態の値: 未着手 / 設計中 / 実装中 / 検証中 / 完了（公開版で検証済み）。

### 課題10とv1.0台帳の関係

2026-11-06のユーザー決定: v1.0は当初の目標どおりとする。SPECの9章・11章に従い、
大容量イメージでのメモリ・応答・取消の測定と、主要な商用復元ソフトとの同一条件比較（復元率・速度・対応範囲）は
v1.0の必須範囲として[v1.0受入台帳](V1_ACCEPTANCE.md)の「性能、fuzz、競合比較」行で管理する。
この台帳の課題10は、v1.0で公開した測定・比較を超える継続的な範囲だけを扱う。

### 優先順位の提案（2026-11-06）

破損したUSB/SDからの復元の実用性を優先し、次の順で進めることを提案している。
FAT12/16（課題3）→ 故障媒体向けイメージ取得（課題11）→ CP932の短い名前（課題13）→ exFATの破損耐性（課題12）
→ 既知ハッシュ照合（課題14）→ HTML/CSVレポート（課題15）→ 断片化動画の再構成（課題5）→ カメラRAW（課題6）。
v1.0の範囲へ前倒しするかは未決定。決まるまではv1.0の達成実績に数えない。

## 課題ごとの記録欄

各課題に着手したら、以下を追記します。設計判断（対応しない組合せとその理由）、
試験コーパスと正解の出所、試験条件数、バイト一致件数、異常系、4ネイティブVMのCI、公開実物の検証記録。
