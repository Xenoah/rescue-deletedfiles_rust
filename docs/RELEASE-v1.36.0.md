# Rescue v1.36.0

Windowsの差分VHDXから論理ディスクを再構成し、そこから削除済みファイルを復元できます。最新の子を入力に選び、直近の親からベースまでを順に追加してください。GUIでも同じ順にファイルを選択できます。4Knの3世代ディスクを検証したCLIの例です。

```sh
rescue import-image --image-type vhdx --source child2.vhdx \
  --segment child1.vhdx --segment base.vhdx --output guest.raw \
  --raw-bytes 100663296 \
  --raw-sha256 cceb17d376c006b3576a71e7efd1e6f76800903ba8791d3fbe835a7e630a8637 --json
rescue scan --source guest.raw --work-dir scan --json
```

長さとSHA-256は検証例の論理ディスク全体の値です。手元のディスクを照合するときは、そのディスクについて別途取得した値を指定します。Rescueは各世代を読み取り専用で開き、子のセクタービットマップを使って、親から継承したセクターと子が書いたセクターを組み合わせます。元のコンテナを移動した場合も、明示的に指定された親のファイル名・有効なデータ書き込みGUID・ディスク識別子・論理セクター長・容量を確認します。

## Windowsで作成・削除したファイルの実証

各構成で、Microsoftの仮想ディスクドライバーから読み出した各世代の全バイトとSHA-256を、Rescueで取り出した論理ディスクと照合しました。さらに最終世代を通常スキャンと索引スキャンのそれぞれで復元し、削除前に保存した各ファイルの全バイトとSHA-256を照合しました。

| 論理セクター | 親から最新の子までの構成 | 全体を照合した世代数 | 原本と一致した削除ファイル |
| --- | --- | ---: | ---: |
| 512バイト | 固定 → 差分 | 2 | 7/7 |
| 512バイト | 可変 → 差分 | 2 | 7/7 |
| 512バイト | 可変 → 差分 → 差分 | 3 | 7/7 |
| 4,096バイト | 可変 → 差分 | 2 | 7/7 |
| 4,096バイト | 可変 → 差分 → 差分 | 3 | 7/7 |
| 512バイト | 可変 → 差分、4 GiB境界前後の2つのNTFS | 2 | 14/14 |
| **合計** | **6構成** | **14** | **49/49** |

3世代の各構成でAVI、DOCX、FLAC、PPTX、SQLite、TAR、WAVの計106,654バイトを復元しました。DOCX・FLAC・PPTX・TARは3世代すべて、残りの3形式は2世代のデータを必要としました。各セクターを実際の親または子にたどって照合しました。GUIでも4Knの3世代を取り込み、7件の復元、同名の別の親を指定したときの拒否を確認しました。[原本別の測定値](vhdx-backing-results.json) · [GUIの測定値と画面](gui-v1.36-results.json) · [Windowsでの512バイト検証](https://github.com/Xenoah/rescue-deletedfiles_rust/actions/runs/44673922816) · [Windowsでの4Kn検証](https://github.com/Xenoah/rescue-deletedfiles_rust/actions/runs/44674698342)

4,192 MiBのGPTディスクでは、4,036 MiBと4,098 MiBから始まるNTFSボリュームに、同名・同内容の7ファイルずつを置いて削除しました。独立した2枚のセクタービットマップに各5個の部分割り当てブロックがあり、全ディスクのスキャンから両ボリュームを区別して14件を復元しました。通常スキャンはMicrosoft予約パーティションをスキップした旨も報告します。最終世代の4,395,630,592バイトのSHA-256は `92fd424c8dcd888b48e71ae605fd871b5525f58868a0a3daf3063ecd4d8126c9` です。[境界試験の測定値](vhdx-bitmap-boundary-results.json) · [Windowsの原本作成・全バイト読み出し](https://github.com/Xenoah/rescue-deletedfiles_rust/actions/runs/44676140287)

## 対応条件と復元できない場合

- クリーンなVHDX v1が対象です。固定または可変容量のベースを含めて最大8ファイル、論理セクターは512または4,096バイト、論理容量は最大64 TiB、割り当て表は最大1,048,576項目です。実用上の上限はブロックサイズにも依存します。
- 親を省略した場合、親の識別子や名前が合わない場合、ログ再生が必要な場合、ブロック状態が未定義・破棄済みの場合、割り当て領域が重複する場合、非ゼロの代替親識別子が指定されている場合は取り込みを中止します。512バイトと4Knの各32例で拒否と未完成出力の破棄を確認しました。構造が正常なままデータを変えた対照も、既知の論理ディスクSHA-256で検出しました。
- 元データが上書き済みの場合や、必要な親が失われている場合は、そのバイトを復元できません。ログ再生が必要な場合は、元メディアのコピーをWindowsなどの対応環境で処理し、そこで検証した論理ディスクを利用してください。
- 対応範囲のVHDX取り込みとNTFSの削除ファイル復元は内蔵機能で動作します。試験ではWindowsの仮想ディスクドライバーを独立した原本の作成・読み戻しに、The Sleuth KitをLinuxでのベースディスクの追加照合に使用しました。
