# RAIDの読み取り専用仮想ソース（alpha.14）

メンバーのRAWイメージと取得マップを読み、`.rescue-raid.json` の指定に従って論理バイトを生成する。
メンバーへ書き戻す処理は持たない。ライブデバイスと入れ子の配列は受け付けず、先にイメージを取得する。
以下の明示プロファイルを実装し、独立生成データとOSの実配列を照合する。

| 方式 | 明示するプロファイル |
| --- | --- |
| JBOD | 指定順の連結。各スロットの使用長を固定。欠損スロットを詰めない |
| RAID 0 | 指定順の通常ストライピング |
| RAID 1 | 指定コピーの同一範囲を照合。読めるコピー間の不一致は欠損扱い |
| RAID 5 | left/right × symmetric/asymmetric。Pの開始位置は左が末尾、右が先頭、1行ごとに回転。非対称はメンバー0からPを飛ばす、対称はPの次からデータを配置 |
| RAID 6 | `pq_last`。末尾2メンバーが固定P/Q、前方がデータ順。P=XOR、Q=Σ(2^i×D_i)、GF(2^8)多項式0x11d。回転P/Qや独自コントローラーの配置は対応と推測しない |
| RAID 10 | 隣接する2メンバーを1ミラーペアとし、ペア間を通常ストライプ化 |

セクター512/4096、ストライプはセクター以上1 MiB以下の2の累乗、2〜16メンバー。
RAID 5は3以上、RAID 6は4以上、RAID 10は偶数。JBOD以外は明示した使用長が等しく、ストライプ境界で終わること。
容量の大きいイメージにはオフセットと使用長を指定できる。マップのセクターが異なる場合は拒否する。
同じ実ファイルを別名・ハードリンクで複数の独立メンバーに見せる設定も拒否する。

欠損は論理オフセットの範囲として伝播する。読めたミラーがすべて一致する場合のみ利用する。
RAID 5/6は既知の欠損数を超える範囲を使わず、残存パリティも照合する。
全メンバーがある場合もP/Qを検証するが、整合する古い配列や誤った構成を正解と保証しない。
パリティ自体が失われたとき、残るデータには独立した内容検証がないことを表示する。

構成作成時は先頭・中央・末尾の各最大64 KiBだけを検査する。ブートの署名はヒントに限り、
通常スキャンによるMFT/FAT等の構造検証とは区別する。マニフェストには正規化したメンバーのパス・
オフセット・使用長・指紋を保存する。セッションと復元レポートにも構成を含める。
MCPはマニフェストだけの許可ではメンバーを読めず、各メンバーを個別に許可する必要がある。

## 構成の選択と操作

GUIでは「RAIDを構成」から方式、順序、欠損位置、開始バイト、使用長を指定する。
保存済みの構成をイメージ欄に入力してから同ボタンを押すと再編集できる。
「指定した構成を検査」はサンプル検査、「構成の候補を探す」はファイルシステム内部構造の照合を行う。
「構成を保存して使用」で仮想ソースを選び、通常のスキャン→選択→復元へ進む。

候補探索はストライプ4 KiB〜1 MiB、RAID5の4配置、任意のメンバー順を試す。
開始位置と使用長は入力値を保持し、コントローラーのメタデータや任意の開始位置は推測しない。
既定は128構成/5秒、最大256構成/30秒、最大32候補。時間制限は構成の間で確認するため、
OSの読取り待ち時間を強制打切りする保証ではない。上限による打切りと取消を結果に明示する。
署名だけで候補にせず、NTFSのMFT/ルート、FAT/exFATの内部構造を各構成最大8 MiBの読取りで照合する。
候補に順位や勝者は付けず、使用する構成を明示して選択する。

```sh
rescue raid --config input.json --search --stripe-sizes 4096,65536 --reorder --json
rescue raid --config selected.json --output array.rescue-raid.json --json
rescue scan --source array.rescue-raid.json --work-dir work --json
```

MCPでは`search_raid`/`create_raid`のジョブを`get_job`で確認する。取消とrequest_idの再送に対応する。
生成した構成も各メンバーの許可に従い、マニフェストの書換えで許可外のソースへ移れない。

## 復元の読取り記録

セッションschema 9は構成と各メンバーの指紋を保持し、再開・復元時に一致を確認する。
ファイル単位の`raid_reads.ranges`には、配列先頭を基準にした論理オフセットと長さ、
使用したメンバー、欠損メンバー、P/Qの位置、利用不能の有無を記録する。スロット番号は0始まり。
この記録は候補検証時の管理情報と実データの読取りを含み、ファイル内容だけの範囲表ではない。
隣接する同条件の範囲を結合し、128範囲を超えた数は`omitted_ranges`に明示する。
JSONレポートとZIP内レポートに同じ構成・読取り記録が残る。

## 検証状況

Linuxで独立したPythonエンコーダーとCLI/MCPを照合し、22条件、44論理像、73復元ファイルが一致した。
RAID6は実装の対数表と異なる多項式演算を正解生成に使用した。全指定配置、欠損位置、
FAT32/exFAT/NTFS、4 KiBセクター、オフセット、パリティ不一致、マップ欠損、構成改変を検査する。

追加のLinuxカーネルmdadm試験は、試験で新規作成したloopだけにRAID5の4配置とRAID6のparity-lastを作り、
停止・切離し後のメンバーをRescueで読み取る。
[全4ネイティブVMのCI 42013561650](https://github.com/Xenoah/rescue-deletedfiles_rust/actions/runs/42013561650)を通過した。
Linuxカーネルの5配列について、欠損条件を含む12論理像・72ファイルを照合。
配布実物は公開後に再実行し、別途記録する。

参照: [Linux raid5.c](https://github.com/torvalds/linux/blob/master/drivers/md/raid5.c)、
