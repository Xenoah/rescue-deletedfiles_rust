# Rescue v1.34.0

Windowsの差分VHDを、指定した親と組み合わせてRAWに変換できます。GUIの「イメージをRAWに変換」で子のVHDを選び、直近の親から順にファイルを指定します。CLIでは親ごとに `--segment` を追加します。

```sh
rescue import-image --image-type vhd --source child2.vhd --segment child1.vhd --segment base.vhd --output guest.raw --json
rescue scan --source guest.raw --work-dir scan --json
```

元の論理ディスクのサイズとSHA-256が分かる場合は、変換時に `--raw-bytes` と `--raw-sha256` を指定できます。照合に失敗した場合は出力を保存しません。

## Windowsでの復元実測

Windows Server 2022で5つの構成を作り、各NTFSボリュームに7形式を書き込んで削除しました。各世代の論理ディスクをWindowsの仮想ディスクドライバーで読み出し、別のディレクトリに移したVHDからも読み出して照合しました。Rescueの出力は全13世代についてWindowsドライバーの全バイトとSHA-256に一致しました。

| 親から子への構成 | 削除したファイル | 原本と全バイト・SHA-256が一致 |
| --- | --- | ---: |
| 固定容量の親 → 差分 | HTML・JSON・RTF・XML・PNG・ZIP・gzip | 7/7 |
| 可変容量の親 → 差分 | 同じ7形式 | 7/7 |
| 可変容量の親 → 差分 → 差分 | 同じ7形式 | 7/7 |
| 可変容量の親 → 差分 → 差分、最後の変更をファイル・ボリュームに書き出してから削除 | AVI・DOCX・FLAC・PPTX・SQLite・TAR・WAV | 7/7 |
| 同じ7形式と書き込み手順で、最後の変更を読み戻して直ちに削除 | AVI・DOCX・FLAC・PPTX・SQLite・TAR・WAV | 0/7 |

最初の3構成で復元した7形式はNTFSのファイルレコード内に収まります。大きい7形式では、親に書いた内容の一部を1段目の差分で変更し、別の512バイトを2段目で変更しました。削除前に書き出したケースでは7件・106,654バイトすべてを復元できました。4ファイルは親と差分2個の計3ファイルから、残り3ファイルは差分2個からセクターを組み合わせています。通常スキャンと索引付きスキャンの両方で確認しました。[各ファイルのSHA-256とセクターの所在](vhd-backing-results.json)

直ちに削除したケースでは、削除直前にアプリケーションが読み戻した内容と、Windowsドライバーがアンマウント後に読んだディスクの内容が異なりました。全7件で、ファイル先頭から4,096～4,607バイトの512バイトだけが一世代前の値でした。NTFSには名前と長さが残っていました。元のファイルのSHA-256を指定する `recover-extents` は、7件すべての保存を拒否しました。

欠落した親、同名で異なるディスクID、壊れたフッター、親の参照領域とデータの重複なども検証しました。親のIDと名前を保ったまま継承するセクターを書き換えた場合は、既知の論理ディスクSHA-256を指定すると変換を拒否しました。GUIでも親2個と論理SHA-256を指定して変換し、出力が検索元に選ばれたことと、別の親を渡した場合に出力が残らないことを確認しました。[GUIの結果と画面](gui-v1.34-results.json)

Rustテスト96件、Clippy、統合試験92組が通過しました。35形式・36原本の比較試験は、意図的な上書きなどを含む1,116条件のすべてで期待した結果となり、1,016条件で原本と全バイトが一致しました。

## 対応範囲

- 固定容量または可変容量のクラシックVHDを親とする、最大8ファイルのチェーンに対応します。全世代の論理容量が一致し、親名・親ディスクIDとWindows Unicodeの親参照が整合する必要があります。各差分内のビットマップを512バイト単位で読み、明示的に書かれたゼロと親から継承するセクターを区別します。
- Windowsが記録した絶対パスを開くことはありません。指定した親ファイルを照合するため、同じファイル名を保って別の場所にコピーした一式も使えます。親の更新日時が記録され、コピー後の日時が異なる場合は、元の論理ディスクSHA-256を指定すると内容で照合できます。
- 親を失うと、その親だけが保持していたセクターは復元できません。VMの保存状態や未対応の親参照を含むVHD、差分VHDXは対象外です。その形式を扱える仮想化環境で、すべての親を使って単独ディスクに統合できれば、そのコピーを入力にできます。
- 対応範囲内の変換に追加ツールは不要です。検証に使ったLinuxのlibvhdi 20240509は固定・可変の単独VHDではWindowsと一致しました。この版で親を指定して差分VHDを読むと3 MiB位置を含む範囲で結果が異なったため、差分の照合にはWindowsドライバーから取得したバイト列を使用しました。
