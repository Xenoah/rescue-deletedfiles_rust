# Rescue v1.46.0

QEMU Enhanced Disk（QED）をRAWに変換できます。単独イメージと、QEDまたは明示的にRAWと記録された親を持つ差分イメージに対応します。GUIの「イメージをRAWに変換」から選べます。CLIでは子を `--source`、親を直近から順に `--segment` で指定してください。

```sh
rescue import-image --source youngest.qed --segment middle.qed --segment base.qed --image-type qed --output guest.raw --json
rescue scan --source guest.raw --mode carve --work-dir scan --json
```

QEDには親のファイル名が記録されます。名前が合っていても、同名で内容が異なる親を区別するには、対象世代の論理ディスクのSHA-256が必要です。既知の値は `--raw-sha256`、バイト長は `--raw-bytes` で指定できます。

## 実際に削除したファイル

Windowsで削除したNTFSファイル、mtoolsで削除したFAT32ファイル、Linuxで削除したext4ファイルを含むディスクを用意しました。QEMU 6.2と10.0で作ったイメージをRescueで読み、通常スキャンと索引スキャンをそれぞれ実行しました。下表は2つのスキャンで共通して原本の全バイトとSHA-256が一致した削除ファイル数です。[原本と再現手順](../tests/qed/README.md)

| ディスク | 構成 | 削除ファイルの完全一致 |
| --- | --- | ---: |
| 単独QED | NTFS・FAT32・ext4を各QEMU版で1件ずつ、計6件 | 44件 |
| 3層の差分チェーン | QED→QED→QEDのext4、QED→QED→RAWのNTFS | 15件 |
| 4 GiB境界をまたぐGPT | ext4パーティションを持つ4,311,744,512バイトの単独QED | 8件 |

9構成で延べ67件、異なる原本は15件です。単独6件と差分2組では、QEDの11世代すべての論理ディスクを原本と比較しました。実際の削除に加えて、子が非ゼロの親データを明示的にゼロにした範囲、短い中間世代の末尾を越える範囲、3つの世代がそれぞれ供給するバイトを照合しています。QEMU 6.2と10.0による独立の読み出し結果が一致しました。[構成別の結果](qed-results.json) · [QEMUの割り当て表との照合](qed-native-results.json)

GPTの試験では、GNU Partedで作ったパーティションをThe Sleuth Kitでも確認しました。8原本のうち4件は4 GiBより前、4件は後で始まります。全ディスクをバイト単位で比較したSHA-256は `43e699ab56a328b1010c0ac798e8973fc64cdf97976b8399d50a778f68690589` です。[ファイル別の開始位置・サイズ・SHA-256](qed-boundary-results.json)

## ゼロが続くディスクの検索

組み込み形式の検索では、1 MiBの読み取り範囲の両端に続くゼロについて、候補の先頭を含み得る範囲だけを検査します。ヘッダーが境界をまたぐ場合の先読みを維持します。ローカルLinuxのデバッグビルドで、64 MiBの同一入力の検索が13.916秒から0.419秒になりました。入れ子のZIPとPNGを含む3候補の位置・ハッシュ・走査バイト数は一致しました。MP4・ICO・GIF・TAR・JPEG・PDF・PNG・ZIPの8形式、末尾が欠けたPNGの拒否、全ゼロを先頭とする利用者定義形式を、通常・索引スキャンで確認しました。[形式別の実測値](sparse-carve-results.json)

## 破損・上限・外部ツール

- 対応範囲内の変換とファイル復元は外部ツールなしで実行できます。1チェーンは最大8ファイル、割り当て表の合計は128 MiB、明示的に割り当てられたデータまたはゼロのクラスタは合計2,097,152件までです。
- ヘッダーや表の範囲外・重複・不整合、必要な親の省略、期待した長さやSHA-256との相違など計49条件を確認しました。失敗時は完成品としてRAWを残しません。
- 整合性チェックが必要なQED、未対応の機能フラグ、ディレクトリを含む親参照、QED以外でRAWと明記されていない親には、対応するQEMU環境が必要です。失われた親にしか存在しなかったデータや、上書き後に別のコピーがない原本を再構成することはできません。

Linux GUIでQEDの3世代を指定し、変換した17,039,360バイトがQEMUで読み出した原本と一致しました。GUIでそのディスクを新規スキャンし、削除済み8件をZIPへ復元しました。展開した31,236バイトと各SHA-256が原本に一致しました。同名で内容が異なる親に置き換えた場合は、指定した論理SHA-256との照合に失敗し、RAWを作成しませんでした。[実測値と11枚の画面](gui-v1.46-results.json)

Rustテスト96件、Clippy、Linuxリリース実行ファイルの統合試験106組が通過しました。既存35形式・36原本による1,116条件が期待結果に一致し、うち1,016条件で原本と全バイトが一致しました。
