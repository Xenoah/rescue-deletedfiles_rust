# Rescue v1.39.0

VirtualBoxの差分VDIで、残っているスナップショット世代を選んで削除ファイルを復元できます。対象の子VDIを指定し、直近の親から固定または可変サイズのベースまで順に選びます。各親のイメージUUIDと更新UUIDを照合し、子が変更したブロック、明示的にゼロにしたブロック、親から読み継ぐブロックを区別してRAWに変換します。

```sh
rescue import-image --image-type vdi --source child2.vdi \
  --segment child1.vdi --segment base.vdi --output guest.raw --json
rescue scan --source guest.raw --work-dir scan --json
```

GUIでは「イメージをRAWに変換」でVDIを選び、親を1行に1ファイルずつ指定します。元の論理ディスクの長さやSHA-256が分かる場合は、GUIの照合欄またはCLIの `--raw-bytes`、`--raw-sha256` で、保存前に確認できます。固定・可変の単独VDIでも利用できます。

## VirtualBox製の差分VMDKの修正

VirtualBoxが作成した一部の差分VMDKでは、親のファイル名を記録せず、親CIDに `ffffffff` を設定し、親を `ddb.uuid.parent` だけで識別します。公開Linux版のv1.33.0・v1.34.0・v1.35.0で子を単独指定すると変換が成功扱いになり、96 MiBの2世代とも4,065,178バイトが元のゲストと異なりました。この版は該当する子の単独変換を拒否し、不完全なRAWの保存を防ぎます。

このVMDKを復元するときは、親子一式をVirtualBoxで読み取り専用で開き、対象世代のディスク全体をRAWとして取り出します。この手順で取得したRAWはWindowsが読んだ全バイトと一致し、NTFSから削除した7ファイルをRescueが通常・索引スキャンの両方で復元できました。[問題を再現した配布物と修正後の実測値](../tests/vmdk-vbox-parent/README.md)

## 実ディスクイメージでの復元

VirtualBox 7.2.22と6.1.50で作成した5組、計19世代のVDIを使いました。各世代をRescueで変換し、ディスク全体のバイト列とSHA-256を元のゲストと照合しました。VirtualBoxの両バージョンでも全世代を読み取り専用で開き直し、同じバイト列が得られました。3組のNTFSにはWindowsディスクドライバーで読み戻した各世代の全バイトを使用しています。[作成方法と原本](../tests/vdi-chain/README.md) · [VirtualBox・ファイル別の照合結果](vdi-chain-native-results.json)

| ゲスト・VDI構成 | 世代数 | 最後の世代から復元したファイル |
| --- | ---: | --- |
| NTFS・固定ベースと差分 | 2 | HTML、JSON、RTF、XML、PNG、ZIP、gzipの7件 |
| NTFS・可変ベースと差分2段 | 3 | 同じ7形式を別のディスクから復元 |
| NTFS・書き込みをフラッシュした可変ベースと差分2段 | 3 | AVI、DOCX、FLAC、PPTX、SQLite、TAR、WAVの7件 |
| FAT32・明示的なゼロと親から読み継ぐ領域を含む差分 | 3 | BMP、GIF、PDF、PNG、WAV、WebP、ZIPの7件 |
| ext4・可変ベースと差分7段 | 8 | 同じ7形式を1世代ごとに1件ずつ削除 |

各構成の最後の世代で通常スキャンと索引付きスキャンを実行しました。削除ファイル35件（異なる原本18件）はすべて全バイト・SHA-256が一致しました。ext4はThe Sleuth Kitでも全世代を読み、削除件数が順に0、1、2、3、4、5、6、7になることを確認しました。各世代に再登場するファイルを含む28件の復元結果も、原本と照合しました。

Linux GUIでは3世代のVDIを指定してNTFSディスクを取り込み、7ファイルをZIPに保存しました。展開した106,654バイトを原本と照合しました。同名の別世代の親を指定した場合は変換を拒否し、出力ファイルは作成されませんでした。[GUIの記録と画面](gui-v1.39-results.json)

## 制限と検証できること

- 対応するのはVDI v1.1の固定・可変ベースと差分イメージです。ベースを含めて8ファイル、割当表は1ファイル64 MiB・合計128 MiBが上限です。全世代の論理サイズとセクターサイズが一致する必要があります。VDI変換自体にはVirtualBoxのインストールは不要です。
- 親の欠落・順序違い、IDの重複・不一致、割当表の破損、照合値違いなど27条件を確認しました。記録されているUUIDを保ったまま親の中身だけが変わる場合は、既知の論理ディスクSHA-256で判別できます。[拒否した条件](vdi-chain-results.json)
- 暗号化VDI、旧バージョン、undo形式には対応しません。これらには対応するVirtualBoxや鍵が必要です。欠けた親、上書き・TRIMで失われた内容を補うには別のコピーが必要です。ext4の削除記録と名前を使う復元にはThe Sleuth Kitを使います。

Rustテスト96件、Clippy、統合試験98組が通りました。ファイル形式の試験では1,116件を照合し、完全一致を期待する1,016件すべてで原本と一致しました。
