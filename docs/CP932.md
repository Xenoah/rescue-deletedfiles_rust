# FATの日本語短名（CP932）

v1.2.0-alpha.2で、FAT12/16/32の8.3名を明示的にCP932で解釈できる。長い名前（LFN）は元からUTF-16で、exFAT/NTFSもこの設定の影響を受けない。既定のASCII動作は維持する。

```sh
rescue scan --source card.raw --fat-short-name-encoding cp932 --indexed --work-dir work --json
```

GUIは詳細設定の「FATの短い名前の文字コード」で「日本語 CP932」を選ぶ。MCPの`start_scan`は`fat_short_name_encoding: "cp932"`を指定する。自動推定は行わない。

## 確認できない部分を残す

FATはOEMコードページを保存しないため、非ASCII短名は選択した文字コードによる解釈であり、元のパスが確認済みとは表示しない。
候補の警告`FAT_SHORT_NAME_BYTES`に8.3名11バイトの16進数、選択したコードページ、削除で先頭バイトが失われたかを保存する。索引・再開・復元JSON・ZIP内レポート・HTML/CSVでも同じ情報を保持する。親ディレクトリーの8.3名も同じ設定で解釈するが、この警告の元バイトは各候補自身の名前である。

削除マーカーE5は失われた先頭バイトを復元できない。ASCIIの1バイトを失った場合と、2バイト文字の先頭を失った場合の両方が成立することもある。区切りが一致する位置までの曖昧なバイトを`?{16進数}`と表示し、両解釈を警告に残す。たとえば削除された`日本語.TXT`の短名は、残ったバイトだけでは`?{FA967B}語.TXT`となる。`本語`等の候補を根拠なく確定しない。

保存時の05は元のE5を表すFAT規則として扱い、削除マーカーとは区別する。CP932のNEC/IBM拡張・半角カナ・Windowsの私用文字も扱う。不正なバイトは黙って置換せず16進数と警告で示す。確認できたLFNがある場合はLFNを優先する。

## セッションの互換性

CP932を選んだセッション/索引はスキーマ10を使用する。旧版が設定を無視してASCIIで再開することを防ぐため、旧版では開けない。ASCII設定の旧セッション/索引は引き続き開ける。索引の再開時は、ヘッダーとチェックポイントのコードページが一致する必要がある。

元バイトのハッシュと現在のソースを復元時にも再検証し、保存済みのコードページで名前を解釈する。文字コードの解釈と、内容の復元成功は別の情報である。

[自動試験](cp932-v1.2.json)：Pythonの独立したCP932符号化を使うFAT12/16/32、CLI/索引/MCP、MBR/GPT、プレビュー、ZIP、HTML/CSV、実プロセス強制終了・再開を確認する。物理媒体の故障や文字コードの自動識別を測定したものではない。
