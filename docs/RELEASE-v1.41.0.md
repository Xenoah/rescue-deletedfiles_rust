# Rescue v1.41.0

ファイル名やディレクトリの記録が失われたディスクから、連続して残った単一ボリュームのRAR 4・RAR 5アーカイブを検索して復元できます。格納・圧縮・ソリッド圧縮、Unicode名、アーカイブコメントに対応します。

```sh
rescue scan --source disk.raw --mode carve --extension rar --work-dir scan --json
rescue recover --session <session> --all --destination recovered --json
```

2行目の `<session>` にはスキャン結果のセッションパスを指定します。GUIではCarvingの拡張子に `rar` を指定し、結果から復元したいアーカイブを選んでZIPに保存します。

## 実際に削除したアーカイブでの検証

RAR 6.23と7.23で作成したRAR 4・RAR 5を各8種類用意しました。FAT32とext4にそれぞれ書き込み、読み戻して原本と比較し、mtoolsとdebugfsで削除しました。通常検索と索引付き検索の両方で、32件すべてが削除前のバイト列・SHA-256と一致しました。独立したUnRAR 6.11と7.23でも復元物をテストし、中の計49ファイルを展開して原本のバイト列とSHA-256に照合しました。ディレクトリ、空ファイル、コメントを持つ6種類では、生成に使ったRARでもコメントを抽出して照合しました。[原本と生成方法](../tests/rar/README.md) · [原本別のSHA-256と独立検証結果](rar-native-results.json)

Linux GUIでFAT32から16件を復元し、ZIPを展開した計212,734バイトが原本に一致しました。HTML・CSVの出力とZIP内の復元記録も照合しました。[GUIの記録と8枚の画面](gui-v1.41-results.json)

Rustテスト96件、Clippy、Linuxリリース実行ファイルの統合試験100組が通過しました。35形式・36原本の回帰試験は1,116条件が期待結果と一致し、そのうち1,016条件で原本と全バイト一致しました。

## 復元できる範囲

- ヘッダーと終端記録を確認し、各メンバーを展開してCRC32またはBLAKE2spを照合します。RAR 5のクイックオープン記録は参照先のヘッダーと比較します。圧縮されたRAR 4コメントと格納されたRAR 5コメントも検証します。
- 暗号化・分割アーカイブ、破損、途中切れ、読み取り不能範囲など26条件を検証しました。コメントと関連するCRCを正しく変更した別アーカイブでは、削除前のSHA-256を与えた `match-hashes` が `not_listed` を返しました。[判定結果](rar-results.json)
- アーカイブと展開後のファイルの合計にはそれぞれ64 MiB、ヘッダーには4,096件、RAR 5の辞書には32 MiBの上限があります。暗号化にはパスワード、分割には必要な各巻と対応するRARツールが必要です。リカバリーレコードからの再構築は外部ツールの対象です。
- 内蔵の内容検索はRescue単体で使用できます。アーカイブの外側の元のファイル名や断片の順序を特定するには、残存するファイルシステムの記録などが必要です。上書きやTRIMで内容が失われた部分をこの検索で再現することはできません。
