# Rescue v1.17.0

ファイル名や配置情報が失われた場合に、HTML5文書とNetpbm画像を連続したディスク領域から取り出せるようになりました。GUI・CLI・MCPのカービングと索引スキャンで利用できます。

```sh
rescue scan --source disk.raw --mode carve --extension html --extension pnm --work-dir work --json
rescue scan --source disk.raw --mode carve --extension html --extension pnm --indexed --work-dir indexed --json
```

## 実測

| 条件 | 結果 |
| --- | --- |
| FAT32に書き込んで読み戻し、削除したHTML文書 | 通常・索引スキャンとも7/7件で全バイトと原本のSHA-256が一致。UTF-8 BOM、日本語、終了タグに似たスクリプト・コメント・属性値、textarea、長い表、暗黙の文書末尾を含む |
| ext4に書き込んで読み戻し、削除したNetpbm画像 | 通常・索引スキャンとも9/9件で全バイトとSHA-256が一致。ImageMagickが生成したP1〜P7、ビット詰め、16ビット濃淡・RGB、アルファを含む。FFmpegでRGBA64に展開し、各原本と復元画像の全画素も照合 |
| GUIで新しくスキャンしたFAT32の削除済みファイル | HTML7件と画像9件の合計16/16件、95,596バイトが一致。ZIP内の各ファイルを原本と直接比較し、CSV・HTMLレポートの16行をJSONと照合 |
| 破損・対象外 | HTMLの16例、Netpbmの14例を拒否。両形式で未読セクターを模擬し、未読領域をまたぐファイルを拒否。その領域の直前までに収まる完全なファイルは復元 |
| 既存の35形式・36ファイルの横断試験 | 1,116件の観測中、1,016件が原本と一致。NTFSの管理情報を消去した連続配置は33/36件、断片化配置は12/36件。全ファイルの内容を上書きした条件は0/36件 |

## 復元条件

HTMLはUTF-8のHTML5 DOCTYPEを持つ文書を最大2 MiBまで扱います。明示的な `</html>` で終了する場合、後続の改行は含めません。htmlタグを省略した文書は、要素の対応とゼロ埋めまたは入力末尾から長さを推定します。SVGやMathMLを混在させた文書、閉じタグの自動補完が必要な断片、旧式の文字コードは対象外です。

Netpbmは画素数・サンプル幅・値域から長さを検証します。連結した画像は1枚ずつ保存します。P1〜P3の余分な空白やコメント、P4〜P6のCRと先頭画素LFの境界には曖昧さがあります。いずれの形式にも原本を識別する内容チェックサムはありません。文字や色だけが変わった上書きの判別には独立した原本ハッシュが必要です。復元に外部ツールは不要です。[対象形式と末尾の扱い](DOCUMENT-CARVING.md)
