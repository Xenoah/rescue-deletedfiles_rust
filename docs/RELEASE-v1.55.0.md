# Rescue v1.55.0

3Dモデルやシーンを保存するBinary glTF 2.0（GLB）の内容検索を追加しました。元のファイル名や開始位置が分からなくても、残っている連続データからファイル末尾を特定し、埋め込みテクスチャやアニメーションを含めて復元します。GUIでは「内容から検索」を選び、対象の拡張子を `glb` に絞れます。

```sh
rescue scan --source disk.raw --mode carve --extension glb --work-dir scan --json
```

Blenderで作った9原本をLinuxのFAT32・ext4に保存・読み戻し・削除し、両ディスクで全18件を復元しました。通常検索と索引検索の両方で全バイト・SHA-256が一致しました。mtools・e2fsprogsで別途作った2ディスクでも18件を照合しています。形状、材質、複数メッシュ、アニメーション、PNGテクスチャ、カメラだけのシーンを含みます。[Linuxの実行ログと原本](../tests/glb) · [全ファイルのSHA-256](glb-native.json)

復元物をBlender 4.3.2に読み込み、頂点座標・面の接続・画像画素・アニメーション名を原本と照合しました。実GUIでもFAT32上の9件を新しくスキャンしてZIPに保存し、全52,520バイトを比較しました。[Blenderでの再読み込み](glb-blender.json) · [GUIの照合記録](gui-v1.55-results.json)

コンテナー64 MiB、JSON 2 MiBまでの自己完結型GLB 2.0に対応します。外部ファイルを参照するモデル、スパースアクセサー、必須拡張を使う圧縮モデル、GLB 1.0は対象外です。その場合はファイルシステムの管理情報・既知の配置などから元ファイルを取り出し、必要な外部素材と拡張対応ビューアーを用意してください。構造上正しい頂点の書き換えは、原本のSHA-256との比較で検出できます。[破損・取得エラー・変更済み頂点の試験](glb-results.json)
