# Rescue v1.24.0

分割RAWを外部ツールなしで結合し、そのままスキャン元に指定できます。連番の先頭を選ぶと数字順に読みます。任意名のセグメントは順番を指定してください。各セグメントの開始位置、長さ、SHA-256と、結合後のディスク全体のSHA-256を記録します。取得時の長さ・SHA-256を指定した場合は、どちらも照合してから新しいRAWを保存します。

```sh
rescue import-image --image-type raw --source disk.001 --output joined.raw --raw-bytes 100663296 --raw-sha256 "$DISK_SHA256" --json
rescue scan --source joined.raw --work-dir scan --json
```

GUIでは「イメージをRAWに変換」で「RAW」を選びます。「元ディスクと照合」を開くと、取得時の長さやSHA-256を指定できます。既存の出力ファイルは保持します。

## 実際に削除したファイルでの照合

| ディスク | 分割方法と結果 |
| --- | --- |
| Windows NTFS 96 MiB | Windows上で実際に削除した7ファイルの内部を境界にして8分割。結合後の全バイトとWindows実測の論理SHA-256が一致し、削除済み7件を復元 |
| FAT32 40 MiB | GNU splitで14分割した場合と、7個のファイルの途中で8分割した場合に、BMP・GIF・PNG・PDF・WebP・WAV・ZIPを各7件復元 |
| ext4 16 MiB | GNU splitで6分割した場合と、同じ7形式の途中で8分割した場合に、各7件を原本と照合 |
| NTFSの記録を4 GiB境界の前後に配置した比較用ディスク | 先頭セグメントは4,294,967,553バイト。4,361,292,800バイトの結合結果全体が原本と一致し、7ファイルの全バイト・SHA-256が一致 |

Linuxの実GUIで3種類の8分割ディスクを結合し、結合結果がスキャン元に設定されることを確認しました。そのRAWからCLIでも各7件を復元しました。誤ったSHA-256を指定した場合は出力を作成しませんでした。通常のGUIでの18件のアーカイブ復元、HTML・CSVレポート、64 MiBの取得中断・再開も検証しました。[ファイル別の照合記録](split-raw-v1.24-results.json) · [GUIの記録](gui-v1.24-results.json)

LinuxでRustテスト96件とリリースビルドの統合試験81群が通過しました。35形式の回帰試験は1,116観測中1,016件が全バイト一致し、欠損・上書きなどの条件別の期待値も一致しました。

## 制限と外部ツール

RAW自体には構成表やハッシュがありません。連番の途中の欠落や同じファイルの二重指定は検出しますが、末尾の欠落、任意名の順序、同じ長さの誤ったセグメントの検出には、取得時に記録した長さやハッシュが必要です。著しく大きいイメージの保存先には、十分な論理ファイルサイズを扱えるファイルシステムが必要です。

セグメントが暗号化、圧縮されている場合は、対応する形式の読み取りが別途必要です。E01・Ex01の検証付き取り込みにはlibewf、AFFの読み取りには対応ドライバーを備えたThe Sleuth Kitを使用します。分割RAWの結合自体は外部ツールを使用しません。実削除試験の再現にはmtools・e2fsprogs、比較用の大容量NTFS試験の作成にはQEMUを使用します。[操作と対応範囲](IMAGING.md)
