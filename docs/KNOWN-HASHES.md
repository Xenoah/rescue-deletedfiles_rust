# 既知のSHA-256との照合

復元時に計算した出力SHA-256と、利用者が持つ既知の一覧を比較します。一致・一覧にない・照合できない結果を分けて記録します。

GUIでは復元後に「保存場所・レポート」を開き、「既知ハッシュと照合」を選びます。UTF-8のSHA256SUMSファイルを指定して「照合する」を押します。「照合結果を保存」は別のJSONを作り、元の復元記録・警告・名前の不確実性も含めます。既存ファイルは上書きしません。

```sh
rescue match-hashes --report recovered/rescue-report-ID.json --checksums SHA256SUMS.txt --output comparison.json --json
```

ZIPの場合は、同梱の `rescue-report.json` を別フォルダーへ取り出して指定できます。GUIではZIP復元直後の結果をそのまま使います。

MCPでは完了した `recover_files` の `job_id` と一覧のテキストを渡します。フォルダー・ZIPの両方に対応します。入力テキストをファイルパスとして解釈しません。

```json
{"name":"match_known_hashes","arguments":{"job_id":"RECOVERY-JOB-ID","checksums":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef  original.jpg\n"}}
```

## 一覧の形式

1行に64桁の16進SHA-256を記載します。ハッシュだけの行、または `SHA256SUMS` の「ハッシュ・空白2つ・名前」「ハッシュ・空白・アスタリスク・名前」を使えます。大文字の16進数、UTF-8 BOM、LF/CRLF、日本語・空白を含む名前に対応します。

名前は照合用のラベルです。絶対パスや `../` に見えるラベルでも、そこを開いたり、ファイルの改名に使ったりはしません。同じ内容に複数のラベルがある場合はすべて保持します。元の名前を一意に確定したことにはなりません。

空行は無視します。重複した同一行、同じラベルに異なるハッシュ、制御文字、GNUのバックスラッシュで始まるエスケープ行は拒否します。ラベルは1〜4096 UTF-8バイト、一覧は4 MiB・20,000行まで。MCPでは通信メッセージの上限も適用されます。復元レポートは16 MiB、保存する照合JSONは32 MiBまでです。

## 結果の意味

- **一致**：完了した復元の記録済みSHA-256が、一覧のいずれかと一致。
- **一覧にない**：照合できる記録済みハッシュが一覧にない。破損の判定ではありません。
- **照合できない**：復元が未完了、エラー・欠損範囲がある、または記録済みハッシュがない。

保存後の出力ファイルは読み直しません。保存後の変更の検出や、外部から渡された復元レポート・既知一覧の真正性確認ではありません。信頼できる削除前ハッシュと照合することで、復元時に保存した内容の一致を判断できます。名前・配置の推定ラベルや警告を取り除くことはありません。

照合JSONには入力一覧の生バイトのSHA-256、復元レポートをJSONとして再シリアライズした内容のSHA-256、比較の基準、集計、各候補の結果、既知内容の全ラベル、元の復元レポートを保存します。後者のダイジェストは元JSONファイルの空白・改行まで含むファイルハッシュではありません。
