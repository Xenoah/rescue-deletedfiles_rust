# FAT12/16/32: v1.1の対応と推定復元

FAT12/16の固定ルートディレクトリー、長い名前、サブディレクトリー、残存する断片化チェーン、MBR/GPT内のボリュームをGUI・CLI・MCPの共通エンジンで解析します。FAT12の12ビット値がセクター境界にまたがる場合も扱います。ボリュームの種類はラベルではなくBPBとクラスター数から判定します。

## チェーンが消えたファイル

通常のQuickでは、元の配置が分からない複数クラスターのファイルを復元しません。v1.1では詳細設定の「FATの連続配置を推定する」を明示的に選べます。CLIは `scan --estimate-fat-contiguous`、MCPの `start_scan` は `estimate_fat_contiguous: true` です。Carvingと同時には使えません。

推定には、使用中ファイルの全探索が完了していること、有効な全FATコピーの対象エントリー（ミラー無効のFAT32では指定されたアクティブFAT）が読み取り可能かつ空きであること、使用中領域と重ならないこと、範囲がボリューム内であることを要求します。残存する途中チェーンは推定で上書きしません。1ファイル64 MiB、形式検証は1ボリューム4 GiBを上限とし、索引の再開時も残予算を保持します。

PNG/APNG、JPEG、PDF、ZIPと対応するOffice/OpenDocument拡張子、MP4/MOV系は既存の構造検証を使い、不正な推定を拒否します。PDFの末尾空白は最大4 KiB許容します。未対応形式には検証できない旨を残します。構造が正しくても元の内容との一致は保証されません。

推定結果には `extent_evidence: estimated_contiguous` と `ESTIMATED_CONTIGUOUS:` 警告を保存します。GUIは「推定（内容未確認）」、復元後は「保存済み（推定）」と表示します。JSONの `completed` は保存処理が完了した意味です。断片化した未知形式は誤った内容を保存し得ます。元のハッシュが分かる場合は照合してください。

## 実測

`1.1.1`、Linuxの実行ファイルで実施した結果です。各OSと公開パッケージでも同じ統合群を必須にしています。

| 検証 | 結果 |
| --- | --- |
| FAT12/16固定ルート・日本語LFN・断片化・境界・MBR/GPT、CLI/索引/MCP | 20項目、60ファイルが元バイトと一致 |
| 明示的推定・中断再開・JPEG破損/断片化・割当競合/ミラー不一致・不完全探索の拒否 | 20項目、10ファイルが元バイトと一致 |
| 未知形式を意図的に断片化した試験 | 1件は内容不一致。「推定・未確認」のまま保持し、成功数に算入しない |
| mkfs.fat + mcopy + mdelによる実削除、FAT12/16各4件 | 全8件一致、うち4件が明示的推定 |
| v1.0と同じ64 MiB FAT32比較イメージ | 標準14/36、推定有効36/36件が元SHA-256と一致 |
| GUIで推定有効化→新規スキャン→選択→ZIP保存 | 36件・152,325バイト一致、22件に推定表示 |

全入力のSHA-256不変を確認しています。比較は連続配置の固定ファイルです。一般的な復元率ではなく、商用製品の今回の再測定でもありません。
