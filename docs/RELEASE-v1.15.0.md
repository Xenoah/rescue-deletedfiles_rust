# Rescue v1.15.0

Btrfsで事前にスナップショットを作成していなくても、削除前の世代がディスクに残っている場合にファイルを取り出せるようになりました。CRC32C、XXH64、SHA-256、BLAKE2b-256の4種類のチェックサムに対応しています。

## 削除前の世代を選んで復元する

GUIの「設定」でボリューム先頭から取得したRAWイメージを選び、「ディスクのツール」から「Btrfsの履歴から復元」を開きます。現行のサブボリュームと過去の世代を選び、候補を表示します。個別にチェックして保存するか、全候補をまとめて保存できます。

```sh
rescue btrfs --source volume.raw --json
rescue btrfs --source volume.raw --current-root 256 --previous-generation 7 --json
rescue btrfs --source volume.raw --current-root 256 --previous-generation 7 --all --destination restored --json
```

世代番号はボリュームごとに異なります。最初のコマンドの `backup_generations` に残っている番号を使います。ディスクの過去の割り当て情報を読み直し、サブボリュームのUUID、ルートの世代、ファイルの各セクターのチェックサムを照合します。削除されたパスのほか、移動・改名で消えた旧パスも候補に含まれます。

## 実ファイルでの実証

| 試験 | 原本と照合した結果 |
| --- | --- |
| ユーザースナップショットなしの復元 | LinuxでTXT、CSV、BMP、WAV、ZIP、独自バイナリ、スパースファイルを実際に削除。無圧縮・Zstandardの2イメージで削除前の世代から7件ずつ復元し、14/14件でバイト列とSHA-256が一致 |
| GUIから選択・保存 | 同じ削除済みZstandardボリュームで、選択した2件と全7件をそれぞれ保存。すべて原本のバイト列・SHA-256と一致し、入力イメージも不変 |
| 3種類の追加チェックサム | Linuxが作成したXXH64・SHA-256・BLAKE2b-256の3ボリュームで、保持されたスナップショットから削除7件ずつを復元。21/21件で原本と一致し、同じファイルをカーネルとbtrfs-progsでも確認 |
| メタデータの破損 | DUPメタデータの片方が壊れても全7件が一致。両方の損傷、破損したスーパーブロック、異なる世代のルート参照を拒否 |
| ファイルの上書き | 1セクターを書き換えた試験で、影響を受けるファイルの保存を拒否。残り6件が原本と一致。削除後の世代を選ぶと候補は0件 |

## 復元できる範囲

単一デバイスのsingle・DUP配置を内蔵リーダーで読みます。過去の世代番号が残っていても、古いツリーやデータが再利用またはTRIMされた場合は復元できないことがあります。複数デバイスのRAIDは対応するLinux環境で別途再構築が必要です。外部エクステントにデータチェックサムがないファイルは、この経路では保存できません。[対応条件とコマンド](IMAGING.md)
